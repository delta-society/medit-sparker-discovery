# 업무에서 KPI 제안하기 — 이익의 아홉 자리

> 0.2 계산/저장 계약의 이력·호환 참조. 신규 0.4 대화는 `objective-linkage.md`를 따른다. 노동시간 분모나 이 문서의 전후 평가 프로그램을 강제하지 않으며 목적 KPI와 외부 측정 연결을 설계한다.

근거: sung이 2026-09-08 이 대화에 제공한 `ai-profit-nine-seats-deck-20260907-1.pdf`, 『이익의 아홉 자리』. PDF 10쪽 생산함수 1~5, 17쪽 수요함수 6~9, 27쪽 계기판. 원문 예시값은 고객 실측이 아니다. 이 참조는 교육 적용이며 덱의 모든 수학·경험적 단정을 채택한 회사 규칙이 아니다.

## 참가자가 KPI를 몰라도 진행하는 대화

참가자에게 'KPI를 정해주세요', '9개 중 고르세요', '목표를 몇 %로 할까요'라고 시작하지 않는다. 기존 업무·제출에서 AI가 **이익 통로 가설 하나, 생산력 KPI 하나, 품질 KPI 하나, 실제 사용 KPI 하나까지** 제안한다. 불필요한 KPI는 빼고 최대 3개만 유지한다. 근거·목표는 AI 제안과 참가자 확인을 구분한다. 분류보다 그 업무의 인과관계가 먼저다.

1. 투입(사람시간·설비·자료) → 품질을 충족한 산출 단위 → 막히는 구간 → AI의 변경 → 늘어난 능력의 실제 사용 → 재무 결과를 업무 언어로 쓴다. 노동시간 감소가 유일한 목표는 아니다. 같은 시간에 더 많은 유효 산출, 기존에 불가능하던 산출, 공동 자산 재사용도 검토한다.
2. 바로 짧은 KPI 초안 표를 보여준다: **지표 / 계산·단위 / 현재 / 목표·확인 상태 / 어디서 확인**. 이름·산식·방향·측정 방법은 AI가 제안한다. 현재값이 없으면 미확인, 수치 목표 근거가 없으면 '기준선 측정 후 설정'으로 둔다. 숫자를 못 정해도 산출 정의·품질 조건·개선 방향·수집 방법을 지금 작성한다.
3. 질문은 결과를 가장 크게 바꾸는 하나만 묻는다. 예: '이 결과는 담당자가 수정 없이 승인해야 1건 완료인가요?' 이미 완료 단위를 알면 '기존 기록에 시작·완료 시각과 수정 이력이 함께 남나요?'처럼 다음 결손만 묻는다. 알려준 사실을 다시 묻거나 전체 설문을 던지지 않는다.
4. 답변으로 KPI·측정 계획을 보정하고 기존 기획서의 `kpi`에 저장한다. KPI만 논의하는 턴에는 전체 개발 명세를 요구하지 않는다. 측정값 없음은 도구 제작·기획 중단 이유가 아니다. 자료 획득 작업을 만든다.
5. 다음 방문에 같은 과제와 KPI를 재사용하고 도입 전/후 관측을 추가한다. 정의·품질기준·업무 구성이 바뀌면 비교 불가 또는 새 기준선으로 명시한다. 예전 목표·관측을 몰래 바꾸지 않는다.

## 아홉 통로 → 업무별 KPI 후보 (정답 선택표가 아님)

| 대상 | 인과관계 질문 | KPI 후보·실현 확인 |
|---|---|---|
| 1 기술수준 | 같은 투입으로 더 많은 유효 산출을 만드는가? | 시간당 품질 통과 산출, 건당 총 사람시간; 검토·재작업 포함 |
| 2 배분효율 | 실제 병목에 시간·자원을 옮겼는가? | 대기·완료시간, 재배치 시간과 그 업무의 산출. 여유시간 자체는 비용 절감 아님 |
| 3 규모의 경제 | 물량 증가로 고정비를 분산하는가? | 품질 통과 산출당 총비용, 추가 고정비/단위 변동비 절감으로 구한 손익분기 물량 대비 실제 물량. 단위·기간 동일, 절감분 양수일 때만 |
| 4 범위의 경제 | 공동 자산이 다른 업무·제품에도 실제 쓰이는가? | 실제 재사용 업무/제품 수와 별도 제작 대비 총비용. 사용처 수만으로 절감액 확정 금지 |
| 5 생산집합 확장 | 전에 못 만들던 산출을 만들 수 있는가? | 새 산출의 품질 통과·실제 사용·유료 수요. 기준선 0일 때 % 증가 금지 |
| 6 이동 | 같은 가격에서 수요·판매가 늘어나는가? | 신규 고객·세그먼트의 실제 사용/구매 전환, 추가 고객획득비용 대비 기여이익. 연락 건수만으로 수요 증가 판정 금지 |
| 7 분할 | 고객층에 맞춘 제품·가격이 실제 수취를 높이는가? | 세그먼트별 실현 가격·기여이익·기존 제품 잠식. 세그먼트 수만 세지 않음 |
| 8 오가격 교정 | 가격 변경이 물량 변화를 고려해 이익을 늘리는가? | 가격·물량·기여이익의 비교, 가격 반응 추정. 마진율을 관측 탄력성으로 대체하지 않음 |
| 9 회전 | 축적·차별화가 고객을 유지하는가? | 이탈·재계약·반복 사용, 계정당 유효 축적량. 현재 가격에서 유지율 관찰만으로 탄력성 변화를 증명하지 않음 |

아홉 개에 맞지 않는 효과를 억지로 넣지 않는다. AR 회수는 원금 회수액=이익이 아니다. AR 업무 처리 생산성은 1·2로, 재무 효과는 회수기간·운전자금·대손 위험 등 별도 설명으로 남긴다. 비용 절감·회수액·추가 매출을 합쳐 같은 이익을 중복 계산하지 않는다.

## 생산력 전후 비교

첫 기본 검사는 **노동생산성 = 품질 기준을 통과한 산출량 / 모든 참여자의 합계 사람시간**이다. 산출의 업무 단위, 난이도·구성, 품질 기준, 사람시간 포함 범위를 맞춘다. 직접 생성시간뿐 아니라 준비·입력·검토·수정·재작업을 포함한다. 전체 경과시간·대기는 별도 지표다. 한 사람 시간만 줄이고 다른 사람 시간이 늘면 모두 더한다.

- 잠재 처리능력과 실제 사용 산출은 따로 쓴다. 사용량·토큰·자동화 기능 수·계획 작성 완료는 생산력 증가의 증거가 아니다.
- 가동률을 쓰려면 같은 단위·기간의 실제 산출/잠재 산출을 사용한다. 매출(원)과 능력(건)을 바로 나누지 않는다.
- 도입 전/후 품질 통과 건수·전체 건수·합계 사람시간을 받고 `kpi.py`로 계산한다. 도우미는 노동생산성 증가·감소·동일, 품질 통과율 하락, 비교 조건 불일치, 측정 대기를 구분한다. 자기보고·합성은 실측 성과로 승격하지 않는다.
- 실제 사용·설비/AI 추가비용·대기시간도 함께 확인한다. 시간당 산출이 늘어도 전사 생산능력·총요소생산성·이익 증가·AI의 인과효과까지 증명한 것은 아니다. 자본 투입이나 병목 밖 변화, 업무 구성 변화 가능성을 명시한다.
- 출처·기간 없이 실측으로 쓰지 않는다. 수치 자료가 없으면 현재/후속 모두 null이고 측정 계획만 작성한다. 한 쌍의 비교는 관찰이며 지속 효과는 다음 비교에서도 확인한다.

## 저장·계산 연결

`python3 <plugin-root>/scripts/kpi.py template`의 객체를 기존 plan의 선택 확장 필드 `kpi`로 넣는다. `plan.py template`의 기존 필드는 그대로 유지한다. KPI가 없는 과거 기획서는 자동 변환하지 않으며 기존 확정본은 reopen 없이 수정하지 않는다. kpi가 있는 리비전은 기존 JSON/한국어 Markdown·해시·이력·show에 함께 보존된다.

`before`/`after`: `kind=unknown|self_report|measured|synthetic`, `window` 관측 기간, `source` 실제 원천; `accepted_output` 품질 통과 산출, `total_output` 동일 집합 전체 산출, `labor_hours` 합계 사람시간, `actual_used_output` 같은 집합 중 실제 사용, `cost` 동일 통화 총비용. 모르는 값은 null. source는 파일/기록 위치 또는 실제 사용자 발화 출처이며 존재하지 않는 링크를 만들지 않는다. 실제 파일 검토 없이 사용자 수치를 실측으로 독립 검증했다고 쓰지 않는다.

`comparability`: `same_unit`, `same_mix`, `same_quality`, `same_labor_scope`는 근거 확인 시 true, 다르면 false, 미확인은 null. 계산을 통과시키려 true로 채우지 않는다.

`metrics` 최대 3개, 각 필드: name, formula, unit, direction(increase/decrease/maintain), target(문자열), target_status(proposed/human_confirmed/unknown), basis. `measurement_plan`: source, collector, window, pairing, frequency. 담당·기간은 참가자가 말한 것을 재사용하며 AI 안이면 제안으로 표시한다.

계산: `python3 <plugin-root>/scripts/kpi.py evaluate --input <새 입력 JSON 또는 저장된 plan.json>` (`--json`은 구조화 결과). 입력은 단독 KPI/plan/저장 리비전 세 형식 지원. 저장 거절이면 동의 없는 임시 파일도 만들지 않고 산식·미확인 상태만 설명한다. 계산을 요청한 경우 계산용 새 임시 입력의 위치·용도를 알리고 작성할 수 있으나 저장 거절 범위를 넘지 않는다.

도우미 출력을 근거로 짧은 판정·다음 측정 행동을 말한다. 결론이나 변화율을 자유 생성으로 뒤집지 않는다. 실제 ST 업무 산식·AR 금액 판정은 별도 `example.py` 계약을 유지한다. KPI 설정 턴을 ST·AR 대표 금액 출력 하나로 대체하지 않는다.
