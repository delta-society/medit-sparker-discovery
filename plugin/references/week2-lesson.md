# Week2 — 강의·실습 진행 계약

참가자에게는 한국어로 진행하고 내부 상태 키는 화면에 노출하지 않는다.

## 진행 순서와 멈추는 지점

| 구간 | 수행 | 완료 관측 / 기다릴 대상 |
|---|---|---|
| bootstrap | 기획 재사용, 제품 생성, 로컬 서버, 브라우저 조작 | 실제 웹 화면·작동 기록. 미확인 UI를 통과로 만들지 않음 |
| spec | 실제 제품의 언어·코드·데이터·저장·재시작 설명 | 참가자가 화면/결과를 확인. 강사 실습① 안내 대기 |
| workstream | 제품 안 흐름 선택, 대표 입력 실행, 완료 기준 | 참가자의 범위/기준 판단 후 다음 강의 대기 |
| baseline | 실습②에서 같은 흐름의 실제 처리를 연결해 끝까지 실행 | 실제 결과 확인 후 휴식/기초지식 강의 대기 |
| improve | 실제 파일 구조 설명, 바꿀 것·유지할 것·예상 결과, 수정 | 같은 입력의 전후 결과를 참가자가 비교. 다음 강의 대기 |
| verify | 정상·정보 부족·다른 입력·재실행 | 기대/관측 대조와 참가자 확인 후 시연 안내 |
| demo | 짝에게 보여줄 실행·수정·검증 순서 | 실제 시연 관측과 시연 준비만 된 상태 구분. 제출은 요청 시만 |

번호는 현재 덱 편집에 따라 달라지므로 슬라이드 숫자로 자동 이동하지 않는다. 제목/실습 번호로 연결한다. 대화·기록에서 같은 workstream을 유지한다.

## 선택적인 lesson 상태

기존 state에 lesson을 추가해 저장한다. 기존 기록을 직접 고치지 않고 update로 새 리비전을 만든다. 과거 lesson 없는 기록은 기존 state와 실제 파일을 읽고 마지막 확인 구간에서 재개한다.

```json
{
  "phase": "bootstrap",
  "waiting_for": "none",
  "product_path": "",
  "local_url": "",
  "workstream": "",
  "acceptance_criteria": [],
  "learner_observation": ""
}
```

- phase: bootstrap/spec/workstream/baseline/improve/verify/demo.
- waiting_for: none/learner/instructor. 참가자의 실제 관측만 learner_observation에 쓴다. 미답변은 빈 문자열이며 확인을 만들어 넣지 않는다.
- product_path/local_url은 실제 생성·실행 뒤 채운다. URL에는 인증 값이나 외부 배포 URL을 넣지 않는다.
- workstream과 acceptance_criteria는 참가자 선택 후 채운다. 초기 제품 제작에는 기획만 사용하며 가짜 scope_confirmation을 쓰지 않는다.
- stage는 기존 도우미와 호환: 시작 bootstrap, 스펙 spec, 선택 workstream, 첫 끝까지 실행 baseline, 수정 change, 검증 test, 시연 demo. 강의 대기는 stage=paused와 lesson.phase를 같이 보존한다.
- baseline/browser/replay/demo 증거도 실제 도구 출력과 파일을 연결한다. 기록 도우미가 사용자 확인이나 실제 실행 진위를 인증하지는 않는다.

## 진행 응답 예시 — 발화 양식이며 실행 증거 아님

첫 화면 뒤: “제품을 열었습니다. [실제 URL]에서 [실제 입력과 결과]를 볼 수 있습니다. 코드는 [실제 경로]에 있고, [실제 데이터 출처]를 사용합니다. 화면에서 결과가 보이나요?”

선정 뒤: “오늘은 [선택한 시작→결과]를 다룹니다. [확인한 기준]으로 완료 여부를 보겠습니다. 실습① 기록을 저장했습니다. 다음 강의 후 ‘실습② 시작’이라고 해주세요.”

수정 앞: “[현재 관측]이 있습니다. [제안 변경]을 하면 [예상 변화]가 나고 [유지 조건]은 그대로여야 합니다. 이 변경으로 진행할까요?”

예시는 변수에 실제 값이 있을 때만 사용한다. 참가자가 먼저 변경/예상을 말했으면 그 답을 재사용한다. 혼자 진행한다고 명시하면 강의 대기는 생략할 수 있지만 사람 판단·실제 결과 확인은 대신 꾸미지 않는다.
