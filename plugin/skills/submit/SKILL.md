# 제출 — 주차별 명령으로 연결

<participant_input>
$ARGUMENTS
</participant_input>

이 스킬은 **라우터만** 담당하며 직접 파일 생성·업로드를 하지 않는다.

1. 현재 사용자가 명시한 주차를 우선한다. 없으면 이 대화에서 확인한 Camp 주차, 진행 중인 `week1`/`week2` 수업 또는 직전에 확인한 제출 대상의 주차를 재사용한다. 이미 답한 주차는 다시 묻지 않는다. 명시 요청끼리 충돌하거나 어느 대상을 말하는지 불분명하면 추측하지 않는다.
2. 주차가 없거나 충돌하면 **“1주차 기획서 제출인가요, 2주차 구현 결과 제출인가요?”**라고 한 번만 묻고 답을 기다린다. 답한 주차를 이 대화에서 유지해 같은 질문을 반복하지 않는다. 답이 불명확하면 파일을 만들지 않고 두 명시 명령을 안내한다. 날짜·파일 수정 시각·기획서 존재만으로 주차를 추측하지 않는다. 2주차도 1주차 기획서를 사용하므로 기획서가 있다고 1주차를 고르지 않는다. 폴더에 두 주차 기록이 함께 있거나 기록만 있고 활성 맥락이 없으면 자동 선택하지 않는다.
3. **1주차**면 `${CLAUDE_PLUGIN_ROOT}/skills/week1-submit/SKILL.md`, **2주차**면 `${CLAUDE_PLUGIN_ROOT}/skills/week2-submit/SKILL.md`를 읽고 해당 절차를 이 대화에서 바로 적용한다. “1주차 기획서 제출 준비로 이어갈게요” 또는 “2주차 구현 결과 제출 준비로 이어갈게요”로 선택을 짧게 드러낸다. 알려진 실습 폴더·과제·리비전·파일 선택·동의를 전달하고 명령 재입력을 요구하지 않는다.
4. 3·4주차 등 지원하지 않는 주차는 이 라우터에서 지원하지 않는다고 알리고 중단한다. 1주차 ZIP으로 대체하지 않는다. 대상 스킬을 읽지 못해도 다른 주차 도우미로 우회하지 않는다.

직접 명령은 `/sparker-discovery:week1-submit`, `/sparker-discovery:week2-submit`이다. 로컬 준비는 실제 업로드가 아니다. 원본 선택·Camp 수집 정책은 대상 스킬의 기존 계약을 유지하며 이 라우터에서 인증·수집 설정을 읽거나 변경하지 않는다.
