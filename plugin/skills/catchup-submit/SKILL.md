# 밀린 과제 회차별 제출

<participant_input>
$ARGUMENTS
</participant_input>

기존 작업을 제출한다. 수업·기획·평가를 처음부터 시키지 않는다. **한 대화에서 처리하되 서버에는 회차별 파일 한 건씩 접수**한다. 현재 지원은 1주차 기획 ZIP, 2주차 구현 ZIP, 3주차 확정 평가 PDF다. 4주차 코드+PDF 운영 접수는 아직 열리지 않았으므로 별도 로컬 준비로 남긴다. 현재 주차를 과거 파일 모두에 적용하지 않는다.

## 기존 결과물 선택

1. 이미 알려진 실습 폴더와 참가자가 명시한 주차·파일을 재사용한다. 없으면 실습 폴더만 묻는다. 그 폴더의 `.sparker-discovery`, `.sparker-implementation`, `.sparker-evaluation`, `.sparker-submissions` 및 최상위의 명시된 제출 ZIP을 확인한다. 홈 전체·인증 폴더·Claude 원본 대화는 탐색하지 않는다. 폴더가 여럿이면 참가자가 지정한 폴더만 추가한다.
2. 요청한 회차마다 기존 제출본을 먼저 재사용한다. 파일 이름/수정 날짜가 아니라 manifest 또는 검증된 저장 기록으로 회차를 확인한다. 여러 과제·버전이 있으면 짧은 업무명과 내용 차이로 하나를 고르게 한다. 다른 프로젝트의 파일을 조용히 합치지 않는다.
3. 파일이 아직 없으면 해당 `week1-submit`, `week2-submit`, `week3-submit` 스킬의 **로컬 준비**만 적용한 뒤 이 흐름으로 돌아온다. W1 기획 초안 제출 허용을 유지하고 W2 실행 증거를 만들어내거나 package 검사를 풀지 않는다. W3은 기존 평가 내용을 먼저 읽고 미확정 문서만 확인받으며 PDF가 낡았으면 같은 confirmed 기록으로 재출력한다. 지금 새로 정리한 내용은 과거에 작성/시험한 것처럼 표시하지 않는다. 미완료 회차를 만들기 위해 다른 회차 제출을 막지 않는다.
4. 준비 가능한 회차/실제 파일/간단한 내용을 한 번에 보여 주고 제출 범위를 확인한다. 사용자가 이미 특정 회차·파일의 제출을 명시했다면 재승인 질문을 반복하지 않는다. 이미 웹앱에 제출한 회차는 기본 제외하고, 재제출은 사용자의 선택이 있을 때만 넣는다. 웹앱 제출 여부를 읽지 못하면 **미확인**이라고 하고, 로컬 파일 존재를 미제출 증거로 삼지 않는다. 최초 연결에는 로그인된 본인 계정을 확인한다. 다른 참가자의 이름·번호를 입력받아 귀속하지 않는다.

## 검사 → 순차 접수 → 재개

도우미는 `${CLAUDE_PLUGIN_ROOT}/scripts/catchup_submit.py`. Python3.9+ 표준 라이브러리만 사용한다. 아래 JSON과 CLI 인수는 호스트가 작성/실행하며 참가자에게 직접 작성하게 하지 않는다.

선택 목록은 프로젝트 안 별도 로컬 파일에 둔다. 각 회차 한 건, 절대 경로이며 week3의 path는 PDF 자체가 아닌 `.sparker-evaluation/<case>` 기록 폴더다. 예시 경로를 실제 파일처럼 사용하지 않는다.

```json
[
  {"week": 1, "path": "/실제/폴더/.sparker-submissions/week1.zip"},
  {"week": 2, "path": "/실제/폴더/week2.zip"},
  {"week": 3, "path": "/실제/폴더/.sparker-evaluation/my-product"}
]
```

```sh
python3 "<도우미>/catchup_submit.py" inspect --items "<선택 목록 JSON>"
```

`ready`인 항목의 `week`, `path`, `sha256`만 새 제출 목록에 복사한다. `blocked` 항목은 원인과 남은 작업으로 표시하고 다른 준비된 항목을 계속한다. 파일 내용·회차가 바뀌면 재검사하고 바뀐 범위를 확인한다. 준비된 목록이 비면 전송하지 않는다.

```sh
python3 "<도우미>/catchup_submit.py" submit --items "<검토 SHA를 포함한 목록 JSON>" --submit
```

- 각 주차의 제출 연결이 없으면 브라우저에서 기존 참가자 계정으로 로그인하고 **표시된 회차의 터미널 연결**에 동의한다. 로그인 세션은 재사용하되 3주차 기존 연결을 1·2주차 권한으로 확대하지 않는다. 따라서 미연결 주차마다 최초 동의가 있을 수 있다. 연결된 회차는 터미널에서 바로 보낸다. 비밀번호/쿠키/토큰을 AI에게 전달하거나 설정 파일에서 읽게 하지 않는다.
- 서버 수신 뒤 같은 intent를 재조회하여 회차·파일 SHA·제출 ID가 일치해야 `submitted`다. ZIP 생성, 브라우저 동의, 업로드 응답 하나는 접수 완료가 아니다.
- 항목 하나가 막혀도 다음 회차를 처리한다. 중단됐으면 **같은 경로·SHA 목록으로 재실행**한다. 도우미는 기존 intent를 재조회하여 성공 건을 다시 올리지 않는다. 응답 미확정 상태를 건너뛰려고 기록을 삭제하거나 새 파일로 복사하지 않는다.
- 이 도우미를 거치지 않고 과거 웹앱에 올린 파일까지 자동 중복 제거한다고 주장하지 않는다. 재접수가 필요하면 새 이력이 남으며 기존 이력을 지우지 않는다.
- 완료 응답은 `1주차 접수 완료 / 2주차 접수 완료 / 3주차 평가 확인 필요`처럼 선택한 모든 회차의 결과와 남은 행동을 보여 준다. 접수 완료는 교육 완주·효과 판정과 다르다. 이미 성공한 항목을 재제출할 필요는 없다고 알린다.

원본 대화 포함은 W1에서 기존에 명시 선택한 범위를 유지한다. 제출을 위해 새 원본 대화·기밀·인증정보를 자동 포함하지 않으며 원본을 자르거나 마스킹해 검사를 통과시키지 않는다. 목록 JSON·참가자 ZIP/PDF·접수 영수증을 Git 또는 공통 플러그인에 넣지 않는다.
