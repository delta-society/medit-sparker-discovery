# 4주차 최종 코드 + 보고서 제출

현재 대화의 제품 폴더·case·4주차를 그대로 쓴다. `week4.py show --root <case>`로 최신 `confirmed`를 확인하고 `bundle`로 만든 최신 `bundle-rNNNNNN/final-code-and-report.zip`만 사용한다. arbitrary ZIP/PDF나 옛 리비전을 보내지 않는다. 묶음이 없으면 최종 확인된 기록으로 `bundle`을 먼저 실행하고 파일을 보여준다. 이미 묶음이 있으면 덮어쓰지 않는다. 준비가 덜 됐다면 week4로 돌아가 필요한 단계만 이어간다.

참가자의 “제출해줘” 또는 이 제출 명령은 전송 요청이다. 이미 요청했다면 다시 동의를 묻지 않는다. 최종 문서 확인만 받은 경우에는 “이 최종 코드와 보고서를 4주차 과제로 제출할까요?”라고 한 번 제안하고, 요청 전에는 API나 브라우저를 열지 않는다.

```sh
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/week4.py" submit --root "<case>" --submit
```

기존 제출 브리지와 동일한 로그인/명부/과제 저장 경로를 사용한다. 첫 연결에서 기존 참가자 계정으로 로그인하고 **4주차 코드+PDF 제출 연결**에 동의한다. 이미 로그인돼 있으면 그 로그인을 사용한다. 이후 유효한 4주차 연결로는 브라우저나 파일 선택 없이 터미널에서 전송하고 서버 접수 결과를 재조회한다. 3주차/collector/Camp 자격을 재사용하거나 조용히 확대하지 않는다. 이름·주차·이미 아는 파일 경로를 다시 묻지 않는다.

`submitted`와 같은 SHA·week=4의 서버 receipt만 접수 성공이다. 참가자에게 4주차 접수 완료와 홈페이지 제출 내역 링크를 알려준다. pending/unknown이면 미확정임을 알리고 같은 명령으로 재개하며 상태 파일을 삭제하거나 새 제출로 바꾸지 않는다. 유효한 연결이 만료·해제되면 브라우저 재연결을 안내한다. 3주차나 웹 수동 제출로 임의 우회하지 않는다. 기존 과제·코드·로컬 진행 기록은 보존한다.

연결 해제: `submission_bridge.py --logout --scope 4`. 자격 파일·승인 URL은 대화/보고서/패키지에 노출하지 않는다. 격리 시험은 별도 loopback origin과 `--local-test`를 지정한다. 파일 전송은 실제 업무 적용·교육 성과 검증이 아니다.
