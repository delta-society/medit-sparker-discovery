# 기획서 완성 플러그인 사용법

기획서 확정이 이 실습의 완료다. 목적 KPI·제품 범위·기존 앱 입력/결과·기록·품질/수용 기준을 사람과 확인하면, API·데이터 스키마·실행 환경·시험 fixture 등 상세 기술 명세는 후속 구현 단계로 남길 수 있다. 기술 미확인을 추가 설문으로 모두 회수하거나 구현 준비/제품 실행을 기획 완료와 동일시하지 않는다. 확정 전에 현재 요약·역할·미결 질문의 대체된 미확정 문구를 정합화하고 불변 이력은 보존한다. 실제 호스트 플러그인 QA·실습 리허설은 참가자 기획 완료와 별도다.

> 최신 기록 우선 보정: KPI·기능 인과 관계와 결과/근거 기록은 남기되 외부 전달처 선택은 필수가 아니다. `record_only`가 기본이며 app/측정 담당 프로그램 미지정으로 확정을 막지 않는다. 기존 업무 앱 입출력 재사용은 유지한다. 상세와 이전 측정 연결 문구의 적용 경계는 `plugin/references/objective-linkage.md` 「기록 우선 보정」을 따른다.

Claude Code와 Python 3가 있는 환경에서 사용한다. 자체 웹앱이나 모델 API 키를 따로 만드는 도구가 아니다. 대화는 사용 중인 Claude Code 모델이 하고, Python은 저장·이력·완료 조건·문서 출력을 담당한다.

## 시작

현재 통합 버전은 **0.6.1**이다. PDF·온보딩·1주차 기능을 포함하며 PDF 출력은 선택 사항이다. 이전 0.5.x 실제 대화 검증은 해당 후보의 이력으로 보존하고, 이 통합 ZIP 전체의 재검증 결과로 대신하지 않는다.

Windows 네이티브와 macOS를 지원 대상으로 한다. Python 3.9 이상이 필요하며 새 교육 환경에는 지원 중인 Python 3.12 이상을 권장한다. 설치 확인은 macOS에서 `python3 -X utf8 --version`, Windows에서 `py -3 -X utf8 --version`으로 한다. Windows에서 `py`가 없다면 `python -X utf8 --version`으로 확인한다. Windows의 Bash/PowerShell 도구 선택은 Claude Code 버전·설정에 따라 다르므로 시작 터미널만으로 단정하지 않는다.

설치는 [AI Sparker 공통 설치 안내](https://github.com/delta-society/medit-sparker-plugin#설치)를 따른다. Discovery와 Camp를 같은 `sparker` 마켓플레이스에서 설치한다. 이 소스 저장소는 독립 마켓플레이스를 제공하지 않는다.

설치 후 Claude Code를 다시 시작하고 자신의 로컬 실습 폴더에서 실행한다.

```text
/sparker-discovery:onboarding
```

1주차 실습을 시작하거나 이어가려면 `/sparker-discovery:week1`을 실행한다. 첫 대화·CLAUDE.md → Skill 만들고 호출하기 → MCP 연결 상태와 활용 체험 → 나머지 핵심 기능·기초 → 내 업무 기획 → 참가자 앱 제출·Slack 다음 주 준비로 이어진다. 이미 한 단계는 반복하지 않고 “skill부터”, “mcp부터”, “기획만”, “제출부터”라고 말해 이동할 수 있다. 중간에 plan/submit 명령을 다시 입력할 필요는 없다.

Skill 제작 체험은 실습 폴더의 `.claude/skills/sparker-practice/SKILL.md`를 만들고 `/sparker-practice`로 직접 실행한다. MCP 연결이 없으면 개념·연결 설계를 체험하며 실제 연결 성공으로 표시하지 않는다. Agent Teams·Hook 실제 설정은 선택 실습이다. 기능 체험만으로 회사 계정 연결이나 수집기 설정이 바뀌지 않는다. 첫 대화·Skill 체험은 Python 없이 가능하고, 기획서 파일 저장에는 Python 3.9 이상이 필요하다.

기존 제출문이나 파일 경로를 함께 주어도 된다. 기획만 바로 할 때는 기존 `/sparker-discovery:plan`도 사용할 수 있다. 예: `/sparker-discovery:plan 예시 weekly-report`. 예시는 `product-compliance`, `spec-policy`, `weekly-report`, `standard-time`이며 설치된 플러그인의 `examples/`에 포함된다.

업데이트는 터미널에서 다음을 실행하고 Claude Code를 다시 시작한다.

```sh
claude plugin marketplace update sparker
claude plugin update sparker-discovery@sparker
```

마켓플레이스 접근에 문제가 있으면 운영진에게 GitHub 접근 권한을 확인한다. ZIP 다운로드는 설치 절차에 필요하지 않다. 작업 기록은 플러그인 캐시 밖의 자신의 로컬 실습 폴더에 저장한다. OneDrive·회사 네트워크 드라이브의 동기화/잠금 동작은 별도 검증 대상이다.

소스 개발 시에는 `claude --plugin-dir ./plugin`으로 실행한다. ZIP으로 검증할 때는 버전별 고정 폴더에 압축을 풀고 `claude --plugin-dir "<압축을 푼 절대 경로>"`로 로드한다. 폴더 바로 아래 `.claude-plugin/plugin.json`이 있어야 하며 실행 중이거나 재개할 세션의 플러그인 폴더를 이동·교체하지 않는다. 기존 네이티브 대화 QA는 압축해제 폴더 로드 방식이며 마켓플레이스 설치 검증과 구분한다. 운영체제별 소스·패키지·실제 검증 범위는 소스 저장소 `docs/platform-compatibility.md`를 따른다.

## 대화

1. 선택한 예시나 기존 제출 원문을 먼저 읽어 업무 범위·시간·측정 계기·자료 위치를 초안에 채운다. 이미 적힌 내용과 이전 답변은 다시 묻지 않는다. 단순/복잡 구분 등 원문의 조건도 유지한다.
2. 목표·활용이 미확인이고 재사용이 타당하면, AI가 남길 데이터·판단 기준·절차와 업무 활용 가설 1~2개를 먼저 제안한다. 선택/수정/아직 모름을 받은 뒤 필요한 기록과 그 활용의 품질·실제 사용 KPI를 연결한다. 확인된 목표는 유지하고 일회성 업무에 재사용을 강제하지 않는다. 선택하지 않은 기능과 숫자 목표를 임의로 추가하지 않는다.
3. 기존 업무 앱의 입력·시작 계기·결과 반영 면부터 재사용한다. AI/코드/사람 역할, 원천 레코드·결과 필드/상태·중복/실패·측정 이벤트 연결을 설계한다. 앱/권한/필드가 미확인이면 획득 작업으로 남긴다.
4. 구현할 범위와 정상·예외 입력에서의 기대 결과를 함께 정한다. 아직 없는 데이터·규칙은 확보할 대상과 방법으로 남길 수 있다.
5. 최종 내용을 읽고 확정하면 구현자가 쓸 기획서가 저장된다. 문서가 생성됐다는 이유만으로 자동 확정하지 않는다.

기획서는 제품 사용자·목표·사용 흐름, 만들 것/만들지 않을 것, 입력과 확보할 자료, 계산·오류 처리 규칙, 정상/예외 시험, 구현 순서·산출물, 다음 행동을 담는다. 참가자에게 빈 양식을 직접 채우게 하지 않고 대화 내용으로 갱신한다.

## 전달 기획서의 범위

회사 정합성 판정과 실제 효과 측정은 외부 프로그램이 담당하지만, 목적 KPI의 제안·사람 확인 및 외부 프로그램 연결 설계는 기획서에 포함한다. 기존 앱에서 입력하고 결과를 사용하는 흐름이 우선이며 별도 폼/대시보드/다운로드 제품은 예외 이유가 있어야 한다. 실제 앱 접속·게시·성과 계산은 하지 않는다. KPI를 아직 선택하지 못하면 초안으로 계속 설계하되 확정은 보류한다. 사람이 확인한 KPI와 미결 연결의 획득 작업이 있으면 계획 확정은 가능하며 live 준비를 뜻하지 않는다.

기존 검토 절차가 있다는 이유로 승인 관리 기능을 추가하지 않는다. 제품 계산의 정확성·정상/예외 처리는 확인하지만 성과 수집 기능은 만들지 않는다. 산출된 `plan.md`를 Claude Code 또는 Codex의 구현 작업에 전달한다. 내부 JSON 전체는 전달하지 않는다. 이 플러그인은 Claude Code용이며 Codex 네이티브 플러그인 설치를 뜻하지 않는다.

질문은 객관식과 주관식을 섞는다. 선택 가능한 내용에는 번호 보기·기타 직접 입력·아직 모름을 주고, 실제 시간·업무 설명·예외는 짧게 직접 받는다. 번호만 답해도 되고 보기 밖의 자기 말로 답해도 된다. 한 번에 질문 하나이며 추가 설명은 선택이다.

플러그인을 업데이트한 뒤 새 Claude Code 세션을 시작한다. 기존 과제 기록 폴더는 지우지 않는다.

## 캠프 과제 제출

캠프의 대화 텔레메트리는 수업·과제 대화 전체를 기록해 델타 운영진 3인이 검토하고, 캠프 종료 후에도 개선·분석에 보관하는 운영 방식입니다. HR에는 요약으로 답하며 특정 대화를 골라 삭제하는 기능은 제공하지 않습니다. **현재 이 안내의 `submit` 기능은 과제 ZIP 준비 기능**이며, 자동 텔레메트리 연결 완료를 뜻하지 않습니다. 자동 수집 시작 방법은 해당 기능이 검증된 설치본에서 안내합니다.

`/sparker-discovery:submit` 또는 “이번 회차 과제 제출 준비해줘”라고 요청한다. 현재 기획서와 회차를 확인하고 **기획서만**, 또는 **기획서와 선택한 세션 원본**을 제출 파일로 만들 수 있다. 초안도 ZIP 내부에 미확정 상태를 기록해 준비할 수 있다. 참가자 앱은 ZIP 내부의 초안 상태를 자동 표시하지 않는다.

원본을 선택하면 그 세션의 대화·프롬프트·응답·실행 결과가 마스킹 없이 포함된다. 중간에 Claude Code를 재시작했다면 관련 세션을 여러 개 고를 수 있다. 선택하지 않은 세션·subagent 파일·외부 첨부는 자동 포함하지 않는다. 민감한 내용이 있는지 실제 파일을 확인한다.

여기서 세션 선택은 ZIP에 넣을 파일 선택입니다. 별도로 연결된 텔레메트리의 수집 범위를 줄이거나 이미 수집된 대화를 삭제하는 설정이 아닙니다. 수업 중 도움이 필요하면 손을 들거나 직접 요청합니다. 기획·전략은 Sung, 가벼운 기술 문제는 Zoon, 무거운 기술 문제는 Xavier가 맡습니다.

ZIP은 실습 폴더의 `.sparker-submissions/`에 준비한다. 안내받은 파일을 확인한 뒤 [참가자 앱](https://leaderboard-production-eac2.up.railway.app/)에 로그인해 같은 주차의 과제 파일로 업로드한다. 앱의 제출 기록에 해당 파일이 나타나야 제출 완료다. ZIP 생성만으로 서버에 전송되지는 않는다. 재업로드 전 기존 제출 기록을 확인한다.

압축 후 5 MiB 한도를 넘거나 손상된 기록이 있으면 원본을 자르지 않고 알려준다. 선택할 세션을 줄이거나 운영진에게 전달 방법을 확인한다. 제출 파일과 실습 기록을 Git이나 플러그인 배포 ZIP에 넣지 않는다.

## 다시 열기

같은 작업 폴더에서 `/sparker-discovery:plan 저장한 과제를 이어서 수정해줘`라고 요청한다. 과제가 여러 개면 어느 과제인지 이름을 붙인다. 확정 뒤 고치면 초안으로 다시 열리고 이전 확정본은 보존된다. 변경 내용을 다시 확정하기 전에는 기존 확정과 새 초안을 구분한다.

## 이번 범위

법령정보센터·Confluence·Jira·Figma·SNS·엑셀의 실제 데이터를 자동 수집하는 플러그인은 아니다. 지금 제공한 업무를 구현 가능한 기획서로 만드는 교육 도구다. 업무 자료·산식·법적 판정·성과 수치는 임의로 채우지 않는다. 법령·경고표지 적용의 최종 판단이나 공정 ST 산식 확정은 해당 업무 검토자가 수행할 조건으로 남긴다.

## 확정 기획서 PDF

기획서 내용에 동의해 확정하면 먼저 기획서가 저장됩니다. 이어서 다음을 묻습니다.

> PDF도 만드시겠어요? Chrome 또는 Microsoft Edge 중 하나가 필요합니다. 이미 설치되어 있으면 추가 설치는 필요 없고, 확장 프로그램이나 `/chrome` 설정도 필요 없습니다.

- **PDF 만들기:** 같은 PC에 A4 PDF를 만들고 파일 링크를 제공합니다.
- **지금은 건너뛰기:** 기획서는 완료 상태로 보관합니다. 나중에 “이 기획서 PDF 만들어줘”라고 요청할 수 있습니다.

PDF를 선택하지 않으면 브라우저를 실행하지 않습니다. 한글 글꼴과 업무 도식 도구는 플러그인에 들어 있습니다. npm이나 추가 Python 패키지 설치는 필요 없습니다. Python은 PDF 선택과 관계없이 기획서 저장에 필요합니다.

PDF에는 결과 요약, 과제 유형에 맞춘 확인 항목, 현재 업무 흐름, 기획서 전체 본문이 들어갑니다. 긴 문서는 여러 장으로 이어집니다. 기획 확정은 구현이나 효과 측정 완료를 뜻하지 않습니다.

PDF 출력이 실패해도 확정한 기획서와 확인 기록은 보존됩니다. AI에게 “확정한 기획서 PDF를 다시 만들어줘”라고 요청하면 같은 리비전으로 재시도합니다. 브라우저가 없거나 회사 정책이 실행을 막으면 운영 지원이 필요합니다. 기존 기획서 수정이나 재확정은 필요하지 않습니다.
