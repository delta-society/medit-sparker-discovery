## 2. 합의할 변경과 제외 범위

KPI 관련 결과/근거·기록 계기/ID·미확인/실패/수정 이력을 보존하며 외부 전달처 선정은 선택이다. 독립 입력 폼/결과 화면은 만들지 않는다.
- **만들지 않을 것:** 원인 가설을 확정 원인으로 자동 판정; 검색 결과 없음만으로 최초 발생이라고 단정; 개선 대책의 자동 현장 적용; 별도 요청 없는 승인 관리 기능; 별도 요청 없는 컨플루언스 자동 게시 및 원문 수정; 기존 앱 재사용 검토 없이 독립 입력 폼/결과 대시보드/다운로드 화면 제작; KPI 미확인 상태에서 기획 확정 또는 단순 문서 생성 수를 업무 완료로 집계
- **AI 역할:** 제안: 본문 기반 증상/조건 비교·근거 요약. 관련 사례가 없을 때 잠정 원인/대책/확인 방법 생성(전체 기획서 확인에 포함된 방식). 과거 원인을 이번 불량의 확정 원인으로 전환하지 않음.
- **코드 역할:** 제안: 대상 자료 조회·검색·중복 통합·원문 링크 보존·사례집 출력
- **사람 역할:** 제안: 원문 근거와 원인 가설 검토, 현장 확인 및 개선 대책 선택

## 5. 기술 규칙과 수용 시험

- **규칙:** 제안: 각 과거 사례의 원문 링크·조회 범위와 문서에 실제로 기록된 원인/대책을 보존한다.
- **규칙:** 제안: 확인된 과거 사실과 신규 원인 가설을 분리한다. 원문에 없는 검증 결과를 생성하지 않는다.
- **규칙:** 제안: 검색 결과 없음·미조회/접근 불가·실제 최초 발생을 구분한다.
- **규칙:** 동일 조회의 페이지 초안과 엑셀에서 사례 ID·출처·원인/대책·미확인 상태가 일치한다. 과거 기록과 신규 가설을 분리한다.
- **규칙:** 페이지 본문과 표의 근거를 추적하며, 원문에 있는 첨부 참조를 읽지 못하면 미조회로 표시한다. 본문 중심을 첨부 없음으로 해석하지 않는다.

### 정상 입력 시험
- **입력:** 합성 Q-001과 가상 S-001/S-002 문서
- **수행:** 합성 S-001/S-002 문서의 제목·본문·ID를 시험 자료로 작성 → 합성 Q-001로 검색·비교하고 두 출력 생성 → 관련 사례가 있을 때 과거 기록·미확인 상태만 출력하는지 확인
- **예상 결과:** S-001/S-002가 출처 ID와 함께 나오고 기록된 원인/대책 및 이번 이슈와의 유사점·차이점이 표시된다. Q-001 원인은 미확정, 과거 검증 결과는 미기재다. 새 가설/대책을 자동 추가하지 않는다. 두 출력 내용이 같다.
- **통과 조건:** 합성 두 문서 누락 없음, 두 출력 출처/내용 일치, 기록되지 않은 검증 결과·새 가설 없음. 시험 설계이며 미실행.
- **시험 담당:** 구현 담당자(역할 제안)

### 예외 입력 시험
- **입력:** 합성 Q-001; S-002 소속 스페이스 접근 실패, 나머지에서 일치 사례 없음
- **수행:** 접근 실패를 합성 응답으로 제공 → 조회 범위·누락·검색 결과 상태 확인
- **예상 결과:** 조회한 범위에서 사례를 찾지 못함과 미조회 스페이스를 표시한다. 최초 발생/전사 사례 없음으로 단정하지 않는다.
- **통과 조건:** 미조회와 검색 결과 없음이 구분되고 신규 원인 제안은 가설로 유지된다. 설계 시험이며 아직 실행하지 않음.
- **시험 담당:** 구현 담당자(역할 제안)

### 정상 입력 시험
- **입력:** 합성 Q-001과 지정 스페이스의 조회 성공 응답; 관련 사례는 빈 목록
- **수행:** 관련 사례가 없는 합성 검색 결과 제공 → 페이지 초안과 엑셀 생성
- **예상 결과:** 조회 범위 내 관련 사례 없음 표시, 최초 발생 확정 없음. 원인/대책은 증상에 기반한 잠정 제안으로 표시하고 확인 방법을 포함한다. 가상의 출처/과거 문서를 만들어내지 않는다.
- **통과 조건:** 가설·확인 방법·대책이 과거 확인 사실과 분리된다. 정확한 원인 정답은 주장하지 않는다. 미실행 시험.
- **시험 담당:** 구현 담당자(역할 제안)

### 예외 입력 시험
- **입력:** 합성 S-001 동일 ID/버전이 두 번 검색됨. 별도 S-003 문서는 같은 증상에 다른 원인을 기록함.
- **수행:** 중복 및 상충 문서 자료 제공 → 두 출력에서 문서 수와 출처별 내용 확인
- **예상 결과:** S-001은 한 행, S-003은 별도 행. 원인 차이를 표시하고 임의로 한 원인을 정답으로 선택하지 않는다.
- **통과 조건:** 중복만 통합하고 별도 출처/충돌은 보존; 페이지와 엑셀 내용 일치. 미실행 시험.
- **시험 담당:** 구현 담당자(역할 제안)

### 정상 입력 시험
- **입력:** 합성 Q-001 메일과 제품/증상/발생 조건이 담긴 텍스트 PDF; 합성 S-001/S-002
- **수행:** 메일+PDF에서 추출 → 페이지별 출처와 비교 결과·엑셀 일치 확인
- **예상 결과:** PDF 페이지/메일 출처를 보존하고 추출 내용으로 비교. 별도 사용자 재입력 폼 불필요. 생성과 사람 검토 완료를 구분.
- **통과 조건:** 예상 결과와 출처/상태가 일치. 미래 구현의 합성 수용 시험이며 현재 미실행.
- **시험 담당:** 구현 담당자(역할 제안)

### 예외 입력 시험
- **입력:** 합성: 메일과 PDF의 제품 정보 충돌, PDF 일부 판독 실패, 같은 메일 재요청
- **수행:** 상충/판독 실패/재요청 입력 제공 → 결과 초안과 기록 상태 확인
- **예상 결과:** 충돌 근거와 판독 실패를 표시하고 값을 임의 보충하지 않는다. 중복 결과/완료 건수 방지 및 기존 사람 수정 보존. 검토 미완료를 완료로 세지 않음.
- **통과 조건:** 예상 결과와 출처/상태가 일치. 미래 구현의 합성 수용 시험이며 현재 미실행.
- **시험 담당:** 구현 담당자(역할 제안)

## 6. 구현 순서와 검증

- **구현:** 확인한 제품 KPI 정의를 기준으로 분석자료 1건의 완료/품질 조건과 검색·작성·검토·수정의 기록 항목을 명세화한다. 회사 공식 KPI와의 관계는 미확인으로 보존하며 수치 목표/현재값을 발명하지 않는다. / 담당: 기획·업무 담당 역할(제안) / 산출물: 확인된 제품 KPI를 기능·기록·수용 시험에 연결한 명세 / 검증: 문서 생성만으로 완료 처리하지 않고, 근거 누락/잘못된 비교가 남은 자료는 완료에서 제외.
- **구현:** 실제 불량 등록 앱/이슈 ID·계기·제품/증상/조건 및 컨플루언스 본문·표, 결과 반환 위치의 필드 확인. 샘플로 어댑터 설계 병행. / 담당: 구현 담당자·업무 담당자(역할 제안) / 산출물: 기존 업무 앱 입력→검색/비교→기존 결과 위치 연동 명세 / 검증: 원천/출력 실제 위치와 권한 확인 상태 구분, 새 폼/결과 앱 기본 생성 없음.
- **구현:** 기존 검색/API를 우선 활용해 본문 검색·중복 통합·근거 비교와 조건부 가설 기능을 구현하도록 세분화한다. / 담당: 구현 담당자(역할 제안) / 산출물: 검색/분석 모듈의 정상·예외 계약 / 검증: 관련 사례 있음/없음·접근 실패·충돌·미확인 가설 표시 확인.
- **구현:** 기존 앱으로 페이지 초안/엑셀 결과를 돌려주는 경로 설계. 실제 게시 허용 여부와 사람 수정 보존·재시도·중복 방지 계약 확인 전 운영 쓰기 금지. / 담당: 구현 담당자(역할 제안) / 산출물: 원천 이슈와 연결된 결과 인계 명세 / 검증: 입력 ID/버전 연결, 실패 구분, 사람 수정 보존, 중복 결과 방지.
- **구현:** KPI 관련 결과·근거·기록 계기/업무·실행 ID·품질 완료·실제 투입시간·관측/추정·실패/수정 이력의 기록 규칙을 명세화한다. 외부 전달은 선택. / 담당: 기획/구현 담당 역할(제안) / 산출물: KPI와 기능에 연결된 기록 명세. 외부 전달처는 미지정 가능. / 검증: 문서 생성≠검토 완료, 경과시간≠인시간, 미확인≠0. 실제 기록 수집 완료를 주장하지 않는다.

## 7. 다음 구현 행동과 남은 질문

- **담당:** 구현 담당 역할(제안)
- **할 일:** 후속 구현 착수 시 대표 메일/PDF·컨플루언스 샘플의 항목/권한/결과 위치를 대조하고 합성 자료로 추출·비교·결과 초안 생성부터 구현한다. 운영 게시/인증 변경은 별도 범위로 유지한다.
- **완료 조건:** 메일/PDF 근거를 보존한 컨플루언스용 결과 초안·엑셀을 샘플로 생성하고 정상/예외 수용 시험 결과를 기록함.
- **남은 질문:** 메일 서비스·식별자/선택 계기, 실제 PDF 구조, 컨플루언스 대상 페이지와 초안 저장/수정 보존 방식 및 권한은 구현 때 확인할 사항.
- **남은 질문:** 회사 공식 KPI와 이번 제품 KPI의 관계는 미확인. 이번 제품 KPI는 사용자가 확인했으며 수치 목표는 미지정.
