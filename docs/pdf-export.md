# DEL-474 — 확정 기획서 로컬 A4 PDF

사람이 기획서를 확정하면 `plan.py finalize`가 불변 JSON/Markdown을 저장·재검증한 뒤 같은 리비전의 PDF를 자동 생성한다. 참가자는 추가 npm/Node/Python 패키지 설치나 명령 실행을 하지 않는다. 기존 Python 도우미와 설치된 Edge/Chrome을 사용하며, 브라우저는 별도 임시 프로필로 실행한다.

## 출력과 원본

A4 세로 210×297mm, 본문 10pt, 번들 Noto Sans KR 글꼴을 사용한다. 확인된 결과 문구를 주제목으로 배치하고 검토 요약·상세 기획·다음 행동·근거의 위계를 구분한다. canonical Markdown 전체를 렌더링한 뒤, 같은 원본 필드와 표시 공백 정규화 후 대응하는 항목만 PDF 표현 계층에서 구조화한다. Markdown 생성 함수나 기존 리비전 바이트는 바꾸지 않는다. 표 머리글 반복, 긴 행 분할, 도식 크기 검사, 렌더·글꼴 완료 신호 후 출력을 적용한다.

Week 0 DWM의 실제 업무 설명을 유형 선정 근거로 사용했다. 개인 원문/인물 정보는 fixture에 복제하지 않았다. 보고, 대사, 업무 실행, 근거 검색, 정합성, 콘텐츠 제작과 공통형을 지원한다. 자동 유형 선택은 저장된 결과·변경 문구에 따른 표현상 분류이며 업무의 사실 판정이 아니다. 품질 조건 또는 사람 역할의 제목/강조만 바꾸고 자료·규칙·개선율을 만들어내지 않는다. 업무 도식은 상세 기획의 해당 절에 배치한다. 실제 SVG 크기에 따라 나누며, 분할 전후 단계의 계속 표식을 유지한다. 긴 도식 제목은 줄여 표시하고 정확한 원문은 본문에 남긴다. 도식 구문에 쓰이는 기호는 표시용 유사 기호로 치환한다.

## 저장·재시도 계약

파생 출력 위치는 `<root>/.pdf-exports/<case>/rNNNNNN/<fingerprint>/`이다. `plan.pdf`, 오프라인 `plan.html`, 해시·브라우저·리비전을 기록한 `receipt.json`을 임시 폴더에서 함께 공개한다. 원본 레코드, 번들 자산, 출력기 코드의 지문이 같으면 기존 파일의 해시를 검증해 재사용한다. 손상된 결과는 덮어쓰지 않고 실패를 반환한다. 같은 리비전의 병렬 출력은 `.lock`으로 차단한다. 중단되어 잠금이 남으면 출력 프로세스 종료를 확인한 뒤 운영자가 잠금만 복구한다.

`finalize` 응답의 기획 상태와 `pdf.status`는 별개다. PDF 실패 시 확정본/확인 기록은 보존되고 실패 코드와 재시도 안내가 반환된다. `pdf <case> --expected-revision N`은 전체 이력을 검증한 뒤 지정한 과거 확정본도 재출력할 수 있다. 초안 출력은 거부한다. 재시도에 reopen·재확정은 필요 없다.

## 실행·보안 경계

Python 표준 라이브러리로 로컬 DevTools WebSocket과 통신한다. Windows Edge/Chrome 기본 설치 위치, macOS Applications, Linux PATH를 탐색한다. 개발 시험용 절대 브라우저 경로는 `SPARKER_PDF_BROWSER`로 지정할 수 있다. 참가자 안내에 이 설정을 요구하지 않는다. 브라우저 부재·조직 정책 차단은 운영 지원 사항이며 설정을 임의로 바꾸지 않는다. OS 탐색 분기는 구현했지만 Windows/macOS 실기기 검증은 아직 미완료다.

문서의 HTML은 실행하지 않고 문자로 처리한다. 외부 이미지·링크는 비활성 표현으로 출력한다. CSP와 브라우저 요청 차단으로 문서의 외부/로컬 파일 로딩을 막는다. Mermaid는 strict 모드이며 설정 지시문·click·지원하지 않는 도식 구문을 거부한다. 과대한 도식이나 너비 초과는 실패로 처리한다. 회사 기획서가 포함된 PDF/HTML도 원본과 동일하게 로컬에서 관리해야 한다. 브라우저 자체의 OS 서비스 통신까지 차단하는 시스템 방화벽 기능은 아니다.

## 자산과 배포

`tools/pdf-assets/`는 개발팀 전용 빌드다. lockfile 기반 `npm ci --ignore-scripts`, `npm run build`로 MarkdownIt·Mermaid·한글 글꼴을 번들하고 실제 포함 패키지의 라이선스 및 SHA-256 manifest를 만든다. 참가자는 완성된 `plugin/assets/pdf/`만 받는다. `scripts/build-package.py`의 명시 목록에 도우미/자산을 추가했다. 배포 ZIP은 약 4.69MB이며 node_modules·개인 자료·시험 코드를 포함하지 않는다. pdfcn/shadcn/Lieflat 코드는 복사하지 않았고 문서 CSS는 자체 작성했다.

Camp 제출은 현재 Markdown+선택 대화 계약을 유지한다. 이번 PDF는 참가자 PC에서 생성·전달하는 출력이다. 제출 ZIP에 PDF를 넣으려면 앱 허용 목록·압축 한도·inspect 계약을 함께 변경해야 하므로 DEL-490/DEL-486 연계 검증에 남긴다.

## 검증

- `python3 -m unittest discover -s plugin/tests -q`: 전체 helper 회귀 시험.
- `SPARKER_PDF_TEST_BROWSER=<browser> python3 -m unittest discover -s plugin/tests -q`: 실제 브라우저 PDF 시험을 포함한 전체 helper 회귀.
- `SPARKER_PDF_BROWSER=<browser> python3 scripts/verify-pdf-export.py --extended --output <새 폴더>`: 배포 ZIP을 풀어 한글/공백 경로에서 3개 합성 시나리오 출력, 별도로 100행 표·본문 Mermaid·외부 이미지/HTML 문자열, linked 계약, 페이지보다 긴 확보/측정/완료 필드, 긴 시험·식별자와 18단계 흐름 시험. pdftotext는 개발 검증에만 필요하다.
- 실패 후 원본 보존, 같은 지문 재사용, 손상 결과 덮어쓰기 거부, 초안 거부, 잠금, reopen 이후 과거 확정본 출력, payload 원문/이스케이프, 번들 해시를 자동 검사한다.

2026-09-08 Linux Chrome/151.0.7922.34에서 위 실제 출력 검증을 수행했다. A4 크기와 한글 텍스트/표의 마지막 행을 확인하고 전 페이지를 이미지로 검토했다. 첫 시각 검토에서 도식의 숫자 엔티티가 그대로 보이는 문제를 발견해 Unicode 표시로 수정하고, 도식 라벨 추출 검사를 추가했다. Windows 네이티브·macOS, 실제 참가자 설치/권한 환경, Camp PDF 업로드는 검증 완료로 주장하지 않는다.

디자인 보완 후 최종 회귀 결과: 실제 브라우저 시험을 포함한 helper 100개 모두 통과(제외 없음). PDF 전용 시험 13개 통과, AR 계산 12개 통과. `git diff --check` 통과. 일반 skill-creator 검사기는 기존 Claude Code frontmatter의 `argument-hint`, `disable-model-invocation`을 지원하지 않아 해당 검사만 통과하지 못했다. 두 필드는 이번 PDF 변경으로 추가한 것이 아니며 기존 Claude Code 계약을 보존했다.


## 디자인 보완·재검토 결과

2026-09-08 사용자 승인으로 목표를 설정해 보완→검증→재보완→확정 루프를 실행했다. 디자인 위계, 텍스트 인지 리듬, 페이지별 정보구조를 맡은 독립 서브에이전트 3기가 검토했다. 최종 보완본에서는 검토 범위 내 높은·중간 우선순위의 미해결 결함이 없다는 판정을 받았다. 이는 문서·코드 검토이며 실제 참가자의 탐색 속도나 인지부하 개선을 실측했다는 의미는 아니다.

- 결과/변경이 정확히 같을 때 요약 중복을 줄이고, 다음 행동의 담당·할 일·완료 조건을 함께 표시한다.
- workflow의 소스 줄바꿈을 PDF에서 단계명/보조 정보로 구분하고 상세 표의 머리글을 페이지마다 반복한다.
- 짧은 정상/예외 시험은 비교표로 배치하며 장문 시험은 세로형 필드를 유지한다. 측정도 긴 값이 있으면 세로형 카드로 전환한다.
- 확보 작업과 legacy/product 구현 단계를 라벨–값으로 분해한다. 데이터 안의 구분자를 임의 파싱하지 않고 같은 레코드에서 만든 필드 힌트와 표시문 대응을 확인한다. 불일치하면 기존 항목을 남긴다.
- 짧은 측정 계획, 다음 행동, linked H3 계약과 목록은 실제 높이를 확인해 함께 배치한다. 전체 절이나 긴 값을 무조건 한 페이지에 묶지 않는다.
- 페이지를 넘는 긴 필드는 소속 절/계약/지표와 실제 필드 라벨을 반복 표 머리글로 표시한다. 값 노드를 이동하며 요약하거나 잘라내지 않는다.
- 이름이 명확한 짧은 숫자 번호 열만 좁게 배분한다. 100행 표 예시는 본문 포함 12→10페이지로 줄었고 모든 행을 보존했다.
- 반복 시험에서 DevTools 포트가 탭보다 먼저 준비되는 시작 경쟁을 발견해, 초기 about:blank 탭 준비를 제한 시간 안에서 기다리도록 수정했다.

7종·49페이지(주간 보고 5, 미수 대사 5, 불량 검색 5, linked 5, 100행 표 10, 긴 필드/18단계 흐름 12, 긴 시험 7)를 전장 렌더로 확인했다. A4·한글·끝 토큰/순서·페이지 경계 밖 글자 없음, 원본 JSON/Markdown 해시 보존, 잘못된 힌트의 원문 유지, linked 표시 필드 보존과 legacy 비표시 자료 배제, 잘못된 Mermaid 실패를 검사했다. 중간 리뷰의 ‘특정 제목 간격 붕괴’ 주장은 PDF 좌표 교차검증으로 입증되지 않아 철회했다.
