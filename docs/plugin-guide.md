# AI Sparker 실습 안내

## 4주차: 동료 피드백으로 제품 수정하기

공통 플러그인 업데이트 후 `/reload-plugins`를 실행하고 기존 제품 폴더에서 `/sparker-camp:start 4주차 수업` 또는 `/sparker-discovery:week4`로 시작하세요. 기존 코드·기획과 동료 인터뷰 전사본을 넣으면 대원칙 확인 → 문제 해석 → 대안 비교 → 해결 기준·반영 범위 선택 → 같은 대화에서 코드 수정·실제 시험 → 본인 확인·최종 코드와 한 장 PDF 묶음 생성으로 이어집니다. 동료에게 다시 피드백을 받는 과정은 선택 사항이며 기다리지 않고 마칠 수 있습니다. 미확인 사항은 그대로 남깁니다. 진행 기록은 `.sparker-week4/<case>`에서 재개합니다.

Discovery 0.15.0부터 `/sparker-discovery:week4-submit`으로 최신 확정 코드·PDF ZIP을 운영 홈페이지의 **4주차 과제로 바로 제출**할 수 있습니다. 첫 연결에서는 본인 로그인과 4주차 제출 연결에 동의하고, 이후 유효한 연결은 터미널에서 재사용합니다. 서버 접수 결과까지 확인합니다. 3주차 PDF 제출은 기존대로 사용합니다. 원본 전사·음성·실제 업무 데이터·자격증명은 최종 ZIP에서 제외합니다.

## 3주차 코드 기반 평가

공통 Sparker 플러그인을 업데이트한 뒤 `/sparker-discovery:week3`으로 시작합니다. Camp 진입은 `/sparker-camp:start 3주차 수업`입니다. 이전 코드를 읽고 여섯 기준으로 상세하게 묻고 답하며, 참가자가 전체 초안을 검토한 뒤 한 장 PDF 평가서를 받습니다. 진행은 `.sparker-evaluation`에 저장해 재개할 수 있습니다. 입력·출력 연결과 제품 수정은 필수가 아니며 기존 1·2주차는 보존합니다. PDF는 Python 3.9+와 기존 Edge/Chrome을 사용합니다. 기존 설치자는 공통 업데이트 안내를 따르며 새 ZIP 설치는 필요하지 않습니다.

Claude와 작은 작업을 해보고, 내 업무에 쓸 기획서를 만듭니다. 이미 설명한 업무와 작성한 기획서는 그대로 이어갑니다.

## 시작

처음 설치할 때는 [공통 설치 안내](https://github.com/delta-society/medit-sparker-plugin#설치)를 따르세요. 설치한 뒤 자신의 실습 폴더에서 Claude Code를 열고 아래 한 줄을 입력합니다.

```text
/sparker-camp:start
```

수업인지 과제인지 확인하고 필요한 준비부터 안내합니다. 계정 연결이 필요할 때는 [참가자 앱](https://leaderboard-production-eac2.up.railway.app/)에서 코드를 만들고 **터미널의 연결 프로그램**에 입력하세요. 비밀번호나 연결 코드는 대화창에 붙이지 않습니다. 기록 연결에 문제가 있어도 실습은 계속할 수 있습니다.

기록은 캠프로 시작한 대화부터 보관됩니다. 델타 운영진 Xavier·Sung·Zoon이 열람하며 캠프가 끝난 뒤에도 개선·분석에 보관합니다. HR에는 운영진이 요약을 전달하고, 특정 대화만 골라 삭제하는 기능은 제공하지 않습니다. 설치나 로컬 저장만으로 서버 전달까지 끝났다는 뜻은 아닙니다.

## 2주차: 내 기획으로 프로그램 만들기

`/sparker-camp:start 2주차 수업`으로 시작하고 기존 기획서 위치나 MD/PDF/ZIP을 알려주세요. AI가 기획서로 제품을 만들어 로컬 웹 화면을 먼저 열고, 사용한 언어·파일 위치·데이터 출처·저장과 재시작 방법을 설명합니다. 화면을 본 뒤 제품 안의 업무 흐름(workstream) 하나를 고르고, 강의에 맞춰 실행·수정 전후 비교·정상/예외/다른 입력/재실행 검증·시연으로 이어갑니다. 실습 사이에는 강의로 돌아가며 “실습② 시작”, “수정 시작”처럼 이어갈 수 있습니다. 이미 진행했다면 “이어서”, “수정부터”, “검증부터”라고 말하세요. 기능만 바로 시작할 때는 `/sparker-discovery:week2`를 쓸 수 있습니다.

확정 기획서는 보존하고 구현 기록을 별도로 저장합니다. 코드·실행 방법·시험 결과는 선택한 파일만 검토용 ZIP으로 묶습니다. 이 ZIP은 기존 앱 기획서 제출과 다른 형식이며, 앱의 2주차 접수 지원은 별도로 확인합니다. 막힌 작업도 중간 기록으로 남길 수 있습니다.

## 대화

1. **작은 작업 해보기** — 업무 메모를 정리하고 원하는 결과로 고쳐봅니다.
2. **반복 요청 만들기** — 같은 요청을 다시 쓸 수 있는 Skill을 만듭니다.
3. **외부 자료 연결 알아보기** — MCP 연결을 확인합니다. 연결이 없어도 어떤 자료를 가져오면 좋을지 연습할 수 있습니다.
4. **내 업무 기획하기** — 기존 업무 설명으로 결과·입력·완료 기준을 정합니다.
5. **과제 제출하기** — 제출 파일을 준비하고 참가자 앱에 직접 올립니다.

“쉽게 설명해줘”, “다음으로”, “기획만 할게”, “제출부터 할게”라고 말해도 됩니다. 하지 않은 단계를 했다고 표시하지 않으며, 건너뛰어도 다음 단계로 갈 수 있습니다. 에이전트·Hook 등 추가 체험은 기본 실습 뒤 원할 때 진행합니다.

## 전달 기획서의 범위

Claude가 초안을 제안하면 맞지 않는 부분을 고쳐주세요. 이미 업무 설명에 있는 내용을 다시 답할 필요는 없습니다. 모르는 자료나 규칙은 미확인으로 남길 수 있습니다.

전체 내용을 확인하고 동의하면 **기획서 확정본을 저장**합니다. 저장만 요청했거나 질문에 답했다고 자동으로 확정하지 않습니다. 기획서 확정은 실제 프로그램 완성이나 성과 측정 완료를 뜻하지 않습니다.

기획서에는 어떤 결과를 만들지, 어떤 자료를 쓸지, 무엇을 바꾸고 바꾸지 않을지, 어떻게 확인할지가 담깁니다. 기술 설정이나 모든 자료 접근 권한을 지금 확보해야 기획을 끝낼 수 있는 것은 아닙니다.

## 밀린 과제 한꺼번에 제출

Discovery0.14.0 이상에서 `/sparker-discovery:catchup-submit`을 실행하거나 “진행한 1·2·3주차 미제출 과제를 한꺼번에 제출해줘”라고 말하세요. 기존 결과물을 회차별로 확인한 뒤 1주차 기획 ZIP·2주차 구현 ZIP·3주차 평가 PDF를 각각 접수합니다. 없는 결과나 시험을 과거에 했던 것으로 만들지 않습니다. 미연결 주차는 처음 한 번 브라우저에서 본인 로그인과 해당 주차 제출 연결에 동의하고, 연결 뒤에는 터미널에서 바로 제출합니다. 일부 실패 시 같은 대화에서 재개하며 이미 접수된 건은 다시 올리지 않습니다. 웹에서 따로 제출했던 내역은 먼저 확인하세요. 4주차 최종 ZIP은 `/sparker-discovery:week4-submit`으로 제출합니다.

## 캠프 과제 제출

`/sparker-discovery:week1-submit`은 **1주차 기획서 ZIP**을 준비합니다. ZIP을 만드는 것과 앱에 제출하는 것은 별개입니다.

1. 안내된 제출 파일을 열어 내용을 확인합니다.
2. [참가자 앱](https://leaderboard-production-eac2.up.railway.app/)에 로그인해 같은 회차를 선택합니다.
3. **과제 파일 → 제출하기**로 파일을 올립니다.
4. 제출 목록에 파일이 나타나는지 확인합니다. 제출 여부가 불확실하면 새로 올리기 전에 계정·회차·기존 기록을 확인하세요.

초안도 제출할 수 있습니다. 제출을 위해 자동으로 기획서를 확정하지 않습니다.

**대화 기록도 ZIP에 넣고 싶다면** 따로 요청하세요. 선택한 세션의 대화·응답·실행 결과가 가려지지 않은 원문으로 들어갑니다. 이 선택은 과제 파일의 구성만 바꾸며, 별도로 연결한 Camp 기록 수집을 켜거나 끄지 않습니다. 파일이 너무 크거나 손상됐다면 임의로 일부를 빼지 않고 해결 방법을 안내합니다.

Slack에는 기획서를 다시 첨부하지 않습니다. **‘다음 주 첫 실행 / 새로 가능해질 일’** 두 항목의 짧은 글을 준비해 직접 게시하세요. 어디에 게시할지 모르면 강사에게 확인합니다.

## 다시 열기

같은 실습 폴더에서 `/sparker-camp:start`를 실행하고 “이어서 할게”라고 말하세요. 저장에 동의했다면 이전 실습의 진행 정보를 참고해 이어갑니다. 새 세션에서는 남아 있는 기록을 확인하며, 기록이 없으면 이어갈 단계 하나만 묻습니다.

수업에서 과제로 바꾸거나 주차가 바뀌면 `/clear`로 새 대화를 만든 뒤 시작하세요. 실습 진행 정보와 기획서는 폴더에 남아 있습니다. 폴더를 옮겼거나 진행 정보를 저장하지 않았다면 마지막으로 한 일을 알려주세요.

기획서를 수정하려면 “이 기획서를 고쳐줘”라고 말합니다. 이전 확정본을 보존하면서 새 초안으로 수정하고, 새 내용을 확인한 뒤 다시 확정합니다. 기획서 파일을 직접 고치기보다 대화로 수정을 요청하세요.

## 확정 기획서 PDF

PDF는 읽거나 공유하기 위한 **선택 사항**입니다. “PDF도 만들어줘”라고 요청하면 저장한 확정본으로 만듭니다. 현재 과제 ZIP에는 기획서 Markdown이 들어가며, PDF는 따로 보관합니다. PDF가 없어도 과제를 제출할 수 있습니다.

PDF를 만들 때는 Chrome 또는 Edge가 필요합니다. 브라우저가 없거나 출력에 실패해도 기획서는 보관됩니다. 나중에 다시 요청하면 됩니다.

## 필요한 준비물

- Claude Code와 자신의 실습 폴더: 모든 실습에 필요합니다.
- Node.js 22.13 이상: Camp 기록 도구에 필요합니다.
- Python 3.9 이상: 기획서 저장·제출 파일 준비에 필요합니다. 첫 대화와 Skill 체험은 먼저 할 수 있습니다.
- Chrome 또는 Edge: PDF를 만들 때만 필요합니다.

## 이번 범위

이 안내는 공통 Discovery 0.15.1의 참가자 흐름입니다. Camp 배포·수집 계약은 변경하지 않습니다. 기획서·제출 파일·동의한 진행 정보는 자신의 실습 폴더에 저장됩니다. 회사 계정 설정이나 외부 업로드를 실습 시작만으로 바꾸지 않습니다.

필요한 기능만 직접 실행할 수도 있습니다: `/sparker-discovery:plan`, `/sparker-discovery:submit`, `/sparker-discovery:week1`. 설치·업데이트 명령은 [공통 안내](https://github.com/delta-society/medit-sparker-plugin#업데이트)에서 확인하세요.

## 주차별 제출 명령

- `/sparker-discovery:week1` → `/sparker-discovery:week1-submit`: 기획서 ZIP (초안 가능, 요청한 경우만 선택 원본 포함).
- `/sparker-discovery:week2` → `/sparker-discovery:week2-submit`: 구현 보고서와 검증된 코드·실행 방법·시험 결과 ZIP. 미완료도 중간 보고서는 만들 수 있지만 완료 ZIP 검사는 생략하지 않습니다. 앱의 2주차 구현 ZIP 접수 지원은 별도 확인이 필요합니다.
- 기존 `/sparker-discovery:submit`과 “제출 준비해줘”는 확인된 주차를 재사용합니다. 주차가 불명확하면 한 번 묻고, 임의로 1주차를 고르지 않습니다.

위 1·2주차 명령은 로컬 파일 준비입니다. 3주차 PDF의 터미널 제출은 아래 안내를 따르며, 4주차 최종 코드·PDF ZIP은 `/sparker-discovery:week4-submit`으로 제출합니다.

## 0.12.0 — 3주차 PDF 직접 제출

`/sparker-discovery:week3-submit` 또는 3주차 맥락의 `/sparker-discovery:submit`은 최신 검토 완료 평가 PDF만 제출합니다. 최초 한 번만 기존 웹 로그인 후 **터미널 연결에 동의하고 제출**을 누릅니다. 이후 30일 연결 유효기간 동안 다른 PDF·리비전·case도 터미널 제출 요청만으로 웹 확인 없이 전송하고 서버 receipt를 재조회합니다. 제출 전용 기기 인증은 프로젝트 밖 `~/.config/sparker-report/`에 0600으로 보관하며 `submission_bridge.py --logout`으로 서버 연결을 해제합니다. 만료/해제된 인증은 제출을 차단하며 재연결이 필요합니다. 코드·원문·Camp 토큰은 전송하지 않으며 보고서 확정과 전송 동의는 별개입니다. timeout은 접수 완료가 아닙니다. 같은 명령으로 재개하면 동일 intent를 조회합니다.

업데이트 후 Claude Code에서 `/reload-plugins`를 실행하세요. 명령이 보이지 않으면 세션을 다시 시작하고 0.12.0 로드를 확인하세요. ZIP을 사용한다면 새 ZIP을 고정 디렉터리에 풀어 `claude --plugin-dir <directory>`로 다시 로드하세요. 구 0.11 PDF는 SHA receipt가 없어 같은 confirmed 기록으로 `evaluation.py --root <root> --case <case> pdf --refresh` 재출력이 필요합니다(재평가/재로그인 요구 아님).
