# Sparker 기획 플러그인 세션 인계

## 확정
- 참가자 실습의 완료는 기획서 확정이다. 기술 명세와 실제 제품 구현은 후속이며 현 단계에 추가 기술 설문을 붙이지 않는다.
- KPI 정의/확인과 기능의 인과 연결을 복원했다. 기존 업무 앱 입출력을 우선 재사용하며, KPI 관련 결과/근거 기록을 남긴다. 외부 전달처 지정은 선택이다.
- 익명 불량 분석 사례: 메일 본문+PDF → 컨플루언스 과거 사례 비교 → 컨플루언스 결과 확인 및 동일 내용의 엑셀. 합성 Q-001/S-001/S-002를 실제 자료로 취급하지 않는다.
- 제품 KPI: 근거가 확인된 분석자료 1건을 검토 완료하기까지 검색·작성·검토·수정 총 사람시간 감소. 회사 공식 KPI와의 관계·수치 목표는 미확인.
- 사람의 전체안 확인 뒤 기획서 확정. 확정본 잔존 미확정 문구를 이번 정리 지시에 따라 편집 정정했다. 로컬 불변 r14는 보존하고 r17을 최종 저장·재조회했다. 저장 이력/런타임 원문은 Git에 올리지 않는다.

## 산출물과 검증
- 현재 기획서: [불량 분석](../examples/quality-analysis/planning.md).
- 코드·템플릿·스킬·패키징: `plugin/`, `scripts/build-package.py`. 이전 단계별 검증은 각 docs/*verification.md에 보존한다.
- 최신 변경의 도우미 회귀/매니페스트/패키지 검증 결과는 이 문서 마지막 항목에 기록한다. 이 세션 채팅과 실제 저장 도우미 실행은 Claude Code 플러그인 전체 대화 시험과 다르다.

## 후속
1. 최신 ZIP으로 실제 Claude Code 전체 대화/저장/수정/확정/재개 시험. 이전 HTTP 402로 막혔던 시험을 통과로 간주하지 않는다.
2. 1회차 발표·실습 시간 리허설. 1회차 발표는 20분이며 기존 PDF/어젠다를 재사용한다.
3. 실제 제품 착수 시 기술 명세: 실행/반영 동작, 자료 구조·상태/중복/재시도, 검색 관련도·조회 범위, PDF/AI 처리와 두 출력 형식, KPI 기록 계기/원천, 시험 fixture, 자료 처리 권한/보존, 실행 환경/한도를 정한다. 합성 자료 개발은 실제 접근 확인과 병행할 수 있다.
