# 운영자 실행 준비표

이 문서는 DEL-483·489·441·486의 실행 준비물이다. 실제 모델 QA는 진행 중이며, 아래 체크리스트 작성이나 자동 구조 검사 통과를 실기기·수업·배포 PASS로 기록하지 않는다. 결과와 담당자의 판정은 각 이슈에 증거를 붙여 별도로 남긴다.

| 고정 대상 | 현재 후보 |
|---|---|
| Claude Code | `2.1.263` |
| 플러그인 | `sparker-discovery 0.5.1` |
| 후보 플러그인 ZIP SHA-256 | `8285dd75065ca944883fa07855b066d0a0c777b225d4aa9e07f7e38533fce04a` |
| 기획서 PDF 내보내기(DEL-474) | 이번 플러그인 후보에서 제외. 포함 여부와 구현·검증 결과를 최종 배포 시 별도 확인 |
| 발표 PDF | DEL-441 리허설용 별도 자료. 기획서 PDF 내보내기 기능과 구분하여 확정본·해시·리허설 결과 기록 |
| Camp 교육 적용 | DEL-489 운영 결정과 DEL-490 실제 대화·브라우저 검증에 따른 조건부 항목 |

ZIP을 다시 만들거나 내용이 바뀌면 새 해시로 후보를 식별하고 영향받는 검증을 다시 연결한다. 이 문서의 해시는 승인된 최종 배포본이라는 뜻이 아니다. 상세 실행기는 [실제 Claude QA](claude-qa.md), 참가자 명령은 [사용법](plugin-guide.md), 제출 파일 계약은 [Camp 제출](camp-submission.md)을 따른다.

## DEL-483 — 실제 MacBook 설치·대화 확인

GitHub macOS VM이나 MacBook 안의 Linux 컨테이너 결과와 실제 MacBook 네이티브 결과를 구분한다. 악성 입력 시험은 이 일반 실기기 절차에 넣지 않고 폐기 가능한 격리 환경에서 수행한다.

- [ ] 담당자·시험 시각·MacBook 모델·CPU·macOS 버전·터미널·Python 버전·Claude 실제 모델 ID를 기록한다.
- [ ] 로컬 일반 폴더에 합성 실습 자료를 준비한다. 한글·공백 경로를 포함하고 iCloud/네트워크 동기화 폴더 사용 여부를 기록한다.
- [ ] `claude --version`, `python3 -X utf8 --version`, `shasum -a 256 "후보 ZIP 경로"` 결과를 고정 대상과 대조한다. 인증 토큰·로그인 파일은 수집하지 않는다.
- [ ] 후보 ZIP을 직접 로드하여 새 세션을 연다. 불러오기에 실패하면 오류를 남기고 새 빈 폴더에 해제해 `.claude-plugin/plugin.json`이 바로 아래 있는지 확인한 뒤 폴더 로드를 따로 시험한다. 두 방식을 구분해 기록한다.
- [ ] 합성 원문으로 시작 → 이미 제공한 정보 재질문 여부 → KPI 모름/수정/거절 → 전체 요약 → 명시적 확인 → 저장을 실행한다.
- [ ] 정상 종료 후 같은 작업 폴더에서 재개하고, 같은 확정 리비전을 Markdown으로 내보낸다. 내용 변경을 요청한 별도 시험에서는 이전 확정본 보존과 새 초안 표시를 확인한다.
- [ ] 저장 거절은 별도 새 과제로 시험한다. 플러그인 기획 저장소 생성 여부와 Claude 자체 대화 기록을 혼동하지 않는다.
- [ ] 설치부터 첫 응답·첫 저장·확정·재개까지 실제 시간을 기록하고, 막힌 질문·셸 명령·경로 오류를 남긴다.

실행 예시의 경로는 실제 후보 경로로 바꾼다.

```sh
claude --plugin-dir "/절대/경로/sparker-discovery-plugin.zip"
```

각 시험의 기록 한 줄은 `환경 / 소스 commit / ZIP 해시 / 모델 / 시나리오 / 입력 / 기대 결과 / 관측 결과 / 소요 시간 / 증거 위치 / PASS·FAIL·미실행 / 판정자`로 남긴다. 합성 대화 발화·응답·필요한 도구 호출, 리비전 번호·해시, 내보낸 Markdown을 함께 확인한다. 공유 전에 로그·스크린샷의 인증값과 개인 경로를 검토한다. `.claude` 전체나 로그인 설정을 증거 묶음으로 복사하지 않는다.

## DEL-489 — 원본 제출 운영안 결정 준비

아래는 운영자가 선택할 안이다. 허용 범위·담당자·저장 위치·열람·보관·삭제 정책은 이 문서로 확정하지 않는다. 기획서만 제출해도 업무 정보가 들어갈 수 있으므로 동일하게 제출 안내와 검토가 필요하다.

| 선택안 | 포함되는 내용 | 참가자가 확인할 사항 | 운영 결정에 필요한 사항 |
|---|---|---|---|
| 기획서만 | `plan.md`, 과제·회차·리비전·상태와 파일 해시를 담은 manifest | 기획서의 업무 정보, 초안/확정 표시, 회차 | 검토 목적·열람자·보관/삭제 처리 |
| 기획서 + 선택한 세션 원본 | 위 파일 + 선택한 UUID의 JSONL 원본. 프롬프트·응답·실행 결과 등이 마스킹 없이 포함될 수 있음 | 각 파일 전체 내용과 선택 목록. 다른 세션·subagent·외부 첨부가 자동 포함되지 않음 | 원본 허용 범위, 선택 동의·거절 방법, 민감정보 발견 시 대응, 원본별 접근·보관/삭제 |

원본 거절 시험에서는 원본 없이 준비할 수 있어야 한다. 정책 미결 상태에서는 실제 참가자 원본을 시험 자료로 쓰지 않고 합성 자료로 절차를 확인한다. 스캐너 경고가 없다는 사실은 민감정보가 없다는 증거가 아니다. 현재 ZIP 한도 초과 시 원본을 자르거나 몰래 제외하지 않고 선택 범위 또는 운영자 전달 방법을 다시 확인한다.

| 결정 질문 | 운영자가 채울 답 |
|---|---|
| 누가 제출 수집·열람·삭제 요청을 책임지고 문의를 받는가? | 담당자 / 연락 표면: **미정** |
| 어떤 참가자·업무·자료의 원본을 어떤 목적으로 받을 것인가? | 허용·제외 범위 / 목적: **미정** |
| 참가자 앱 파일과 운영자 다운로드 사본의 실제 저장 위치는 어디인가? | 시스템 / 위치 / 사본 책임자: **미정** |
| 누가 원본과 기획서를 각각 볼 수 있으며 접근 회수는 누가 하는가? | 역할 / 접근 부여·회수 담당: **미정** |
| 언제부터 얼마나 보관하며 종료 시 무엇을 삭제하는가? | 기간 / 기산일 / 종료 조건: **미정** |
| 삭제 요청은 어디로 받고 이전 제출·다운로드·백업 사본은 어떻게 처리·확인하는가? | 접수 / 처리 범위·기한 / 확인 방법: **미정** |
| 원본 거절·선택 철회와 제출 이후 민감정보 발견은 어떻게 처리하는가? | 대체 제출 / 교체·회수·연락 절차: **미정** |

참가자 안내 초안 — 대괄호를 운영 결정으로 채운 뒤 배포한다.

> 이번 회차 제출 자료는 [목적]에 사용하며 [열람 역할]이 확인합니다. 제출 범위는 [허용된 선택안]입니다. 세션 원본을 선택하면 선택한 파일의 대화·프롬프트·응답·실행 결과가 마스킹 없이 포함될 수 있으므로 파일 전체를 확인해 주세요. 원본을 포함하지 않는 방법은 [기획서만 준비하는 절차]이며, 선택 변경·삭제 요청은 [담당자/접수 방법]으로 문의해 주세요. 자료는 [저장 위치]에서 [보관 기간과 시작점] 동안 보관하며 [삭제 범위/절차]에 따라 처리합니다. ZIP 준비는 업로드가 아닙니다. 참가자 앱에서 회차와 파일을 확인해 업로드하고 제출 기록을 확인해 주세요.

## DEL-441 — 1회차 시간 리허설

[1회차 어젠다](../curriculum/week1-agenda.md)의 발표 20분·실습 45분을 기준으로 실제 시간을 잰다. 현재 문서의 옛 30분 장표 배분을 진행표로 쓰지 않는다. 발표자는 별도로 확정한 PDF와 발표자 노트의 파일명·해시를 먼저 기록한다. PDF가 준비되지 않았으면 플러그인 실습 리허설만 수행하고 전체 리허설 완료는 남겨 둔다.

| 구간 | 진행 대본·행동 | 기대 결과·관찰 기록 |
|---|---|---|
| 시작 전 | 합성 원문·후보 ZIP·네이티브 설치·모델 사용 가능 여부 확인. 강사와 관찰자 지정 | 환경/해시 일치, 설치 지연은 본 실습 시간과 별도 기록 |
| 발표 0–20분 | 확정된 발표 자료와 노트대로 진행 | 장표별 실제 시간, 20분 종료 여부, 설명이 막힌 지점 |
| 실습 0–5분 | “기존 합성 제출에서 시작해 주세요.” | 원문 선반영, 출처 표시, 첫 응답/저장 시간 |
| 실습 5–15분 | “수치는 모릅니다.” 또는 KPI 후보를 수정 | 근거 없는 수치 생성 없이 KPI 선택·미확인 표시 |
| 실습 15–25분 | 제안한 기능 하나를 반대하고 다른 범위를 선택 | 선택 이유·비포함 수정, 이전 답 재질문 여부 |
| 실습 25–35분 | 기존 앱 입출력·결과/근거 기록·정상/예외 기준 검토 | 실제 접근 미확인은 확보 작업으로 남음 |
| 실습 35–45분 | 짝/강사 피드백 → 전체 요약 확인 → 명시적 확정 | 사람이 읽은 기획서 확정본. 미결이면 초안과 막힌 이유 기록 |
| 별도 후속 확인 | 정상 종료·재개·내보내기, 정보 부족/충분/제안 반대 3종 비교 | 동일 과제와 확정본 보존, 소요 시간·질문 수·실패 복구 증거 |

Camp를 넣기로 결정한 경우에만 합성 ZIP 준비 → 선택 파일/회차 검토 → 허가된 시험 계정의 브라우저 업로드 → 제출 기록 확인을 추가한다. 추가 소요 시간을 별도 기록하고 실습 40분 이상 확보 여부를 다시 확인한다. 로컬 ZIP 생성으로 제출 완료를 선언하지 않는다.

| 실패 | 현장 복구·기록 |
|---|---|
| 인증/사용량/네트워크 실패 | 원문·기존 기록 보존, 발생 시간·오류를 비밀값 없이 기록. 사용 가능 상태를 확인한 뒤 재개. 반복 호출로 해결됐다고 간주하지 않음 |
| 경로/실행기/저장 잠금 오류 | 실행한 명령·셸·경로 기록. 실행 중인 쓰기 작업이 없는지 확인하고 담당자가 잠금 원인을 조사. 과제 폴더를 삭제해 복구하지 않음 |
| 시간 초과·미결 KPI·확정 거절 | 초안과 다음 질문을 남김. 결과를 강제 확정하지 않고 남은 시간과 지원 필요 기록 |
| ZIP 한도/원본 형식 오류 | 원본 보존, 허용된 파일 선택을 다시 확인하거나 운영자에게 전달 방식 확인 |
| 업로드 응답 불명확 | 앱의 기존 제출 기록부터 확인. 무조건 재업로드하지 않고 파일·회차·기록을 대조 |

## DEL-486 — 설치·업데이트·롤백·인계

| 단계 | 작업 | 인수 근거 |
|---|---|---|
| 설치 | 배포 후보 해시 확인, 개인 로컬 작업 폴더에서 새 세션으로 ZIP 로드. 지원되지 않으면 새 빈 폴더에 해제해 로드 | CLI/Python/OS, 직접 ZIP 또는 폴더 로드 방식, 플러그인 이름·버전, 첫 실행 결과 |
| 업데이트 | 기존 세션 종료 후 이전 ZIP·작업 폴더를 보존. 새 ZIP은 별도 파일로 받고 새 세션에서 로드. 기존 과제를 읽어 리비전·확정 상태 확인 | 이전/새 ZIP 해시, 변경 전후 같은 과제의 리비전·해시, 오류 유무 |
| 롤백 | 새 버전 사용을 멈추고 이전 ZIP으로 새 세션을 시작. 기존 데이터 복사본에서 먼저 읽기 호환성을 확인한 뒤 담당자가 복구 방법 결정 | 이전 버전이 새 기록을 읽는지 실제 확인. 실패 시 원본 보존·변경 내역과 오류 인계 |
| 인계 | 소스 commit/PR, 후보 ZIP, 기획서 PDF 내보내기 포함/제외 상태, 별도 발표 PDF, 설치 안내, QA·리허설 증거, 알려진 제한, 담당자/다음 행동을 묶어 전달 | 배포 담당자의 검토 기록과 실제 전달본 해시 |

업데이트·롤백을 이유로 `.sparker-discovery/`, `.sparker-submissions/`, 참가자 원문 또는 기존 Claude 대화 기록을 지우거나 덮어쓰지 않는다. 예전 ZIP을 다시 로드하는 것만으로 데이터 호환성이 보장되지는 않는다. 플러그인 배포 ZIP에 참가자 기록·QA 출력·인증 파일을 넣지 않는다.

최종 인수에는 다음을 확인한다.

- [ ] DEL-483 실제 MacBook, DEL-484 Windows, DEL-485 적대적 대화의 대상 버전·증거·판정·남은 제한이 연결되어 있다.
