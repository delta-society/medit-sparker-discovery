# 참가자 흐름·문구 검증 — Discovery 0.7.0

## 변경

공통 `/sparker-camp:start` 뒤 핵심 실습·재개·기획·제출을 연결한다. 진행 정보는 허용된 실습 폴더에 열거값만 남기는 선택 기능이다. 직접 호출한 plan/submit/week1은 유지한다. Skill/MCP 뒤 추가 기능 체험은 선택이며, Week 1은 제출 파일 준비·앱 업로드 안내를 PDF보다 먼저 한다. 기획서만 ZIP에 담는 것이 기본이고 원본 포함 요청은 기존 명시적 선택 절차를 따른다. PDF는 보관·공유용 별도 파일이다.

## 검증

- 플러그인 회귀 107개 중 102 PASS, 브라우저 환경 검사 5 SKIP. 기존 PDF 코드 변경은 없다.
- QA 실행기 회귀 48 PASS.
- 매니페스트·diff 검사 PASS, 패키지에 learning-progress.md 포함 및 참조 누락 없음.
- 실제 Claude Code 2.1.263 / Haiku, 격리된 합성 실습 폴더에서 다음을 확인했다.
  - 저장된 진행(first_chat/memory/Skill 완료, MCP 개념 완료·실제 읽기 막힘, next=plan)을 읽고 첫 체험을 반복하지 않고 기획으로 이동했다. 새 파일 저장 거절을 유지했다.
  - 초안 ux-draft의 기획서만 제출 ZIP으로 준비했다. 실제 ZIP은 manifest.json·plan.md 두 파일이며 원본 없음, revision 1·draft 유지. PDF 생성·앱 업로드 없음.
  - 사용자 보고에 근거해 first_chat=done, memory=skipped, next=skill_create만 로컬 진행 파일에 저장했다. 업무 내용·대화·계정·기획서 상태는 저장하지 않았다.
- 독립 에이전트가 지적한 기존 JSON/리비전 노출 지시 충돌과 재개 시 원문 재요청 순서를 정리했다. 대화 시험에서 드러난 긴 경로 라벨·중복 상태표와 재개 명령 문구를 보완했다.

## 범위

진행 보존은 호스트 파일 도구를 사용하는 스킬 지침이며 독립 DB/결정적 상태 머신이 아니다. 링크·손상·스키마 오류에서 원본을 유지하고 대화로 재개하는 규칙을 갖는다. 이번 합성 대화는 모든 모델·회사 PC의 전체 수업 인수를 뜻하지 않는다. 실제 고객 제출·계정 연결·기록 수신·강사 리허설을 실행하지 않았다. 원문/확정/제출 계약과 이전 실패 기록은 보존한다.
