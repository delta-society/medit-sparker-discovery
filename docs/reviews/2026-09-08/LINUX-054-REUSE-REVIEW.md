## P2 — 제외한 생산 기능을 참조 활용의 선행 구현으로 유지

`reuse-unknown/evidence/turn-3-input.json`은 신규 ST 초안 검토 참조 **만** 선택하고 편차 분석을 제외한다. T3 최종 응답과 r3 전체 계획을 대조했다.

- `selected_change.non_goals`는 제외 의미를 “반복 이탈 공정 자동 탐지, 주간 트렌드 분석”으로 좁혔다.
- `responsibilities.code`는 4개 라인 Excel 연결과 누락/이상치 표시를 유지했다.
- `implementation_steps[1].action`은 “편차 계산, 누락·이상치 표시 구현”을 새 구현으로 지시한다.
- `quality_conditions`는 매칭·누락·이상치 표시 품질을 제품 요건으로 유지했다. `linkage.downstream`도 새 표시와 누적을 결합한다.
- `acceptance_tests.at01`은 새 편차 계산, at03은 누락 표시 생성을 시험한다. 원문 이력 보존이나 기존 산출물을 입력으로 읽는 것과 구분된다.

개선된 부분도 있다. 신규 참조 정상 시험 at02와 “유사 사례 0건일 때 값을 생성하지 않음” 예외 시험 at04는 추가됐다. r3는 draft, 목표는 proposed/confirmation=null이며 선택을 전체 확정으로 확대하지 않았다. 따라서 0.5.2의 **참조 시험 누락**은 해소됐지만 **선택 범위에 없는 생산 기능 구현 유지**는 남았다.

기존 데이터가 필요하다는 이유로 해당 데이터를 생산하는 기존 업무까지 새 제품으로 만드는 의존관계가 원인이다. 구체 보완안은 “기존/제공된 검토 기록 읽기 → 유사 사례 조회 → 출처·조건·근거 제시 → 사람 ST 검토”로 범위를 한정하고, 자료 미확보는 획득 작업으로 남기는 것이다. 제외된 계산/표시 생성은 코드·구현·제품 시험에서 제거한다. 이후 0.5.5 후보는 별도 해시·실제 T3 전체 계획으로 검증하며 이 실패를 소급 변경하지 않는다.

## 나머지 케이스

- `reuse-confirmed-time` 2턴: 확인된 업무 1건당 분 KPI 유지, 미확인 단위는 질문/잠정 표시, 다른 활용 선택 강제 없음. T2는 기록 계기·실패/중단 표시를 제안하고 draft 유지했다. 수동 과정의 병목 후보는 hypothesis 및 가설 참조로 표시되어 확정된 현재 사실과 구분한다.
- `reuse-one-off` 2턴: 일회성 Word 편집만 유지, 축적/재사용/새 시스템/외부 발송 제외. T2 새 리비전은 사용자 범위 유지 사실만 추가했다. 목표는 형식 불일치 0건이라는 제안이고 전체 확정은 하지 않았다.
- `reuse-weekly-report` 2턴: 선택 후 ST·대시보드·자동 알림·입력 가이드 생성을 제외하고 기록/검토 범위로 좁혔다. 정상·미수신 예외 시험은 보고서에서 누락/수정 이유를 확인할 수 있는지로 연결했다.

### 주간보고 제안 표시 명확성 — P3 관찰

`reuse-weekly-report/evidence/turn-2-records.json`, r2 `linkage.upstream.trigger`는 **“매주 금요일 담당자 수동 취합”**, basis는 원문 f01이다. 원문은 취합을 말하지만 수동 여부를 말하지 않는다. 다만 이 객체는 status=unknown인 연결 설계 초안이며, 현재 현업이 수동이라고 명시하지 않는다. **제안 실행 계기일 수 있으므로 이것만으로 P2 현재 사실 날조로 판정하지 않는다.** 제안 부분의 가설 표시와 source basis를 명확히 하면 좋다는 P3 관찰이다. 같은 최종 화면도 수동 주장을 하지 않는다.

`objective.definition`은 기록된 건수/전체 주간 보고 건수이며 방향은 기록 완비율 증가다. quality에는 검토자가 즉시 찾을 수 있어야 한다고 적지만 실제 재사용·검토 결과 측정과는 거리가 있다. 이는 제안 KPI의 품질 관찰이며 사람 확인된 KPI 날조로 판정하지 않는다.

9턴 모두 draft/proposed 또는 unknown을 유지했고 원문 복사와 불변 리비전 검사에 통과했다. 이 구조 통과가 범위 보존의 의미 실패를 상쇄하지 않는다. 0.5.5 검증은 별도 문서에 기록한다.
