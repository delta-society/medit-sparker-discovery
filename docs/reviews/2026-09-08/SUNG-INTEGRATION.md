# Sung 0.4.2 첨부 ZIP 분석·선별 통합

사용자가 제공한 `sparker-discovery-plugin-0.4.2.zip`은 86,904 bytes, SHA-256 `54f406f496c479ce7c1064635153b7bf6062e09bf1d599f15462ea1112d57a1f`이며 31개 파일을 포함한다. 첨부 코드를 먼저 실행하지 않고 파일 내용·Git blob·diff를 검토했다. 첨부 지침은 통합 검토 대상이며 작업 권한 지시로 취급하지 않았다.

## 출처를 확인할 수 있는 범위

2026-09-08 `origin`을 fetch한 비 shallow 저장소의 전체 로컬 참조 이력과 대조했다. 31개 중 24개는 기존 Git 파일과 바이트 단위로 같다. `8d1f705f6b754f22d0380db09b0490d91a5fc90a`와 그 앞 `57f693f4b76adb718b93f6a1b3ab1151431e9afe` 계열이 24개 일치한다. 새로 가져온 이슈 시작 브랜치도 같은 기반 파일을 포함하므로 ZIP의 정확한 출발 커밋 하나를 식별할 수는 없다.

나머지 7개 blob은 가져온 이력에 없다: plugin manifest, USER-GUIDE, conversation, objective-linkage, submission.py, plan SKILL, test_reuse_flow.py. 따라서 **기존 Git 소스 기반의 추가 수정본**이라는 근거는 있지만, 로컬 편집인지 아직 공유되지 않은 커밋인지, 누가 어느 도구에서 수정했는지는 ZIP만으로 확정하지 않는다. ZIP 전체와 일치하는 공개된 원격 커밋도 확인되지 않았다.

## 채택한 변경과 충돌 해결

| 첨부 변경 | 통합 결정 |
|---|---|
| 활용 가설을 먼저 보여주고 선택/수정/아직 모름을 받는 흐름 | plan skill·conversation·objective-linkage에 채택. 이미 목표/활용이 확인됐거나 일회성 업무인 예외를 유지 |
| 축적→활용→품질/실제 사용 KPI·기록 연결 | 기존 objective/linkage 필드를 재사용. 새 필수 스키마·자동 수집·외부 전달 요구 없음 |
| 미선택 활용 제외·가설과 실제 선택 발화 분리 | 채택. 활용 선택을 전체 KPI/계획 확정으로 확대하지 않음 |
| submission.py 질문 후보 순서 | 해당 문장만 채택. 현재 portable stdio는 유지 |
| 신규 test_reuse_flow.py | 내용 검토 후 통합하고 UTF-8 읽기를 명시. 합성 저장·재개 테스트이며 실제 대화 증거와 구분 |
| USER-GUIDE의 고정 압축해제 폴더 안내 | 현재 OS·Camp 안내를 유지하며 채택. ZIP 임시 경로 재개 실패는 첨부 측 관측으로만 취급하며 이 분석에서 재현했다고 주장하지 않음 |
| 예시 5개 | 기존 최상위 examples와 동일. 별도 기능 변경 없음 |

이전 ‘목표 KPI부터’ 문구와 새 흐름이 동시에 적용되지 않도록 신규 미확인 목표·타당한 재사용의 경우에만 활용 가설을 먼저 제안하도록 정리했다. 확인된 시간 KPI는 바꾸지 않고, 선택하지 않은 기능·새 DB·대시보드·학습 모델을 자동 추가하지 않는다. 원문 보존·추론 구분·Windows 실행·Camp 인계 지침도 유지했다.

## 덮어쓰지 않은 구버전 파일

첨부 plan.py는 기존 Git 기반 버전과 같다. 이를 현재 코드 위에 덮어쓰면 이후 추가한 UTF-8 BOM 처리, Markdown 원시 바이트/CR 무결성, 메타데이터 포함 저장 크기 제한, 공개 전 재검증이 사라진다. 구버전 example/kpi/submission의 실행부와 기존 테스트로 교체해도 portable 출력·Windows 인코딩 보완이 퇴행한다. 첨부에는 최신 Camp·QA·portable 파일도 없다. 전체 ZIP 교체 대신 확인된 추가 변경만 통합했다.

## 검증 범위

선별 통합 직후 신규 합성 테스트 2개를 포함한 plugin 테스트 91개가 통과했다. 이는 대화 흐름이 실제 모델에서 지켜진다는 증거가 아니다. 0.5.2 후보의 실제 QA에는 활용 미확인→선택, 확인된 시간 KPI 유지, 일회성 업무, ST 외 주간 보고 사례를 추가한다. 기존 0.5.1 실행 결과와 새 통합 후보 결과를 구분해 기록한다. 후보 해시·원격 SHA·최종 결과는 최종 live QA 보고서를 따른다.
