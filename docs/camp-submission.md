# Sparker Camp 제출 기능

## 2026-09-08 인터뷰 후 운영 요구사항

캠프 운영 요구사항은 **회차별 수업·과제 세션의 대화 전체 자동 수집**으로 구체화됐다. [텔레메트리 계약](camp-telemetry.md)과 [참가자 안내·운영 절차](camp-telemetry-operations.md)를 따른다. 원문은 델타 운영진 3인이 열람하고 캠프 종료 후에도 개선·분석에 보관하며 특정 대화 선택 삭제는 제공하지 않는다. HR에는 요약으로 답한다.

아래는 이미 구현한 **수동 과제 ZIP 경로의 동작과 검증 이력**이다. ZIP에 넣을 세션을 고르는 기능은 자동 텔레메트리의 수집 범위·제외·삭제 설정이 아니다. 기존 ZIP 기능이 자동 수집·재전송·세션 분석을 수행한다고 해석하지 않는다. 새 텔레메트리의 실제 저장 위치·연결·권한 검증은 별도 구현과 인수에서 확인한다.

## 기존 구현

2026-09-08 사용자 요청: 전략기획팀용 `xavierchoi/delta-insight-relay`를 레퍼런스로 삼아 캠프용으로 보완한다. Discovery에 `submit` 스킬과 로컬 제출 묶음 도우미를 추가했다. 이번 구현은 기존 참가자 앱의 로그인·과제 업로드를 사용한다. 별도 Relay 서버·새 인증코드·대화 자동 수집 훅은 추가하지 않는다.

## 확인한 맥락과 구현 선택

- DWM MCP `mbk-medit`의 09-03 결정은 파일 제출을 참가자 앱으로, 09-08 결정은 관리·제출 검토를 camp 어드민으로 모은다. 09-08 Discovery 완료 기준은 사람이 검토한 기획서 확정이며 기술 구현·실제 성과 측정은 후속이다.
- 기존 Relay는 전략기획팀용이었다는 사용자의 설명을 적용한다. 참고 코드 SHA `c691dcec6d72664032709108681f1546f3f10d04`, 버전 1.5.0. 코드의 일반 교육 설명만으로 Sparker 운영 연결을 추정하지 않는다.
- 참가자 앱 원격 main SHA `439d2ba491cef5f2a4c01947a03a1577491672d9`의 `src/lib/api.ts`, `store.ts`를 확인했다. `/api/submissions`는 로그인 세션에서 신원을 얻고 주차 1~4, 파일 또는 URL 하나, 파일 최대 5 MiB를 받는다. ZIP을 별도로 금지하지 않는다. 재제출은 이전 기록을 보존하고 같은 주차 최신 제출을 바꾼다.
- 해당 앱의 사용량 토큰은 `/api/usage`용이다. 이를 대화 제출 인증으로 재사용하지 않는다. `medit-sparker-plugin`의 집계값만 전송하는 기존 경계도 유지한다.
- 이 도우미 구현 시에는 원문 운영 방침이 미정이었다. 이후 사용자 인터뷰로 위 운영 요구사항을 정했다. 이번 도우미는 실제 참가자 원본을 가져오거나 운영 저장소를 변경하지 않았다. Slack·콘솔 통합의 완료와 새 Claude 텔레메트리 구현 완료는 구분한다.

## 파일 계약

```text
week1-<case>-r<revision>.zip
  manifest.json
  plan.md
  sessions/<선택한 UUID>.jsonl    # 원본 포함을 선택한 경우만
```

manifest의 `format`은 `sparker-camp-submission-v1`. `week`, `plan`(case_id/revision/status/plan_sha256), `sessions`(session_id/file/records), `files`(path/bytes/sha256), `raw_session_records`, `scope`, `identity_source`, `bundle_id`를 가진다. `bundle_id`는 해당 필드를 제외한 canonical UTF-8 JSON의 SHA-256이다. 사용자 이름·이메일·로컬 경로·토큰을 메타데이터로 별도 추가하지 않는다. **원본 대화 자체에는 그 정보가 포함될 수 있다.** 마스킹/익명화된 데이터셋이 아니다.

기획서는 기존 Store의 전체 리비전 체인·Markdown 일치를 확인하고 `expected-revision`으로 고정한다. 과거 JSON·사람 확인 이력을 ZIP으로 복사하지 않는다. 기획서가 초안이면 manifest에도 draft이며 제출 준비가 기획 확정을 만들지 않는다.

원본은 UTF-8 JSON 객체 행, 파일명의 UUID와 일치하는 sessionId, 선택 프로젝트와 일치하는 cwd 근거가 있어야 한다. 프로젝트를 옮겨 작업한 세션은 자동 합치지 않는다. 이 형식을 충족하지 않는 호스트/구버전 기록은 거부하고 원본은 보존한다. subagent 기록·외부 첨부는 포함하지 않으므로 완전한 호스트 세션 아카이브라고 표현하지 않는다.

입력 파일당 20 MiB, 원본/기획서 합계 50 MiB, 최대 32세션, 압축 후 5 MiB 한도다. ZIP 검사 시 파일 수·경로·암호화·링크·압축 방식·압축 해제 크기·해시·목록 일치를 확인한다. 임의 경로를 추출하지 않는다. private-key/GitHub/API/AWS/Bearer 형태 탐지는 보조 경고이며 비밀값을 출력하거나 민감정보 부재를 보장하지 않는다.

원본 읽기 전후 파일 식별자·크기·mtime/ctime을 대조하고 변경 시 실패한다. 이후 기록이 추가돼도 생성한 ZIP은 준비 시점 스냅샷이다. 동일 입력·주차·리비전·원본 선택으로 재실행하면 동일 ZIP 바이트를 재사용한다. 다른 내용은 기존 파일을 덮어쓰지 않는다. 협력적인 사용자 소유 로컬 디렉터리를 전제하며 로컬 공격자에 대한 서명/신원 인증은 아니다.

## 제출·운영 경계

참가자가 ZIP을 검토한 후 기존 앱에서 같은 주차를 선택해 업로드한다. 현재 앱은 manifest를 파싱하지 않아 회차 자동 선택·과제 ID 색인·원본 분석을 수행하지 않는다. 파일과 manifest는 운영자가 내려받아 대조할 수 있다. 준비 결과 `prepared_locally_not_submitted`와 실제 앱의 제출 ID/파일 기록은 서로 다르다.

후속 자동 제출이 필요하면 참가자 앱에 제출 전용 권한·업로드 영수증 조회·멱등 키·선택 범위/보관 계약을 구현해야 한다. 현 사용량 토큰·브라우저 쿠키 추출·전략기획팀 Relay 주소로 우회하지 않는다. 대용량 원본이나 원본 전용 보관이 필요할 때도 이 계약을 먼저 확장한다. 이번 범위의 실제 배포·참가자 자료 제출은 수행하지 않는다.

검증 결과는 [검증 기록](camp-submission-verification.md)에 기록한다.
